## 할 일
1. **도구 확인·설치** (이미 있는 것은 건너뛴다)
   - Android SDK: `build-tools;36.0.0`, `ndk;28.2.13676358`, `cmake;3.22.1`, `platform-tools` (sdkmanager)
   - Rust(rustup) stable + 대상 4개(`aarch64-linux-android x86_64-linux-android armv7-linux-androideabi i686-linux-android`) + `cargo install cargo-ndk --version 4.1.2 --locked`
   - MSYS2 + `make unzip zip pkgconf`(+ 필요하면 gcc). 빌드 셸 PATH 에 `C:\msys64\usr\bin` 추가
   - `ANDROID_NDK_HOME` = SDK 의 ndk/28.2.13676358
2. **저장소 최신화**: `C:\Users\Ahn SH\dev\ash-reader` 에서 main 최신으로.
3. **로컬 버전 규칙 만들기** (작은 코드 수정, PR)
   - `buildSrc/src/main/kotlin/AshBuild.kt` 의 `ashVersionCode()`·`ashVersionName()` 이 CI 가 아닐 때 Gradle 속성 `ash.baseRun`(또는 환경변수 `ASH_BASE_RUN`)을 읽게 한다.
   - 노트북 빌드: versionCode = 1000 + baseRun + 1 (CI 같은 번호 판 위에 덮어 설치 가능), versionName = `1.0.0-rc.<baseRun>-local`.
   - baseRun 은 `gh run list --workflow build.yml --branch main --limit 1` 의 실행 번호로 자동으로 채우는 스크립트(`scripts/local-build.ps1`)를 만든다. 스크립트는 키 비밀번호를 묻는 부분을 대표님이 직접 입력하게 한다(파일에 저장 금지).
   - CI 동작은 바꾸지 않는다.
4. **서명 연결 확인**: `ASH_KEYSTORE_FILE` 은 `.ash-keys` 안의 키 파일 경로, `ASH_KEY_ALIAS` 는 키 별칭. 비밀번호 두 개는 대표님이 입력. 서명된 APK 의 인증서 SHA-256 이 `AE:6D:B1:29:…:25:B6:F1`(D-014)로 시작·끝나는지 `apksigner verify --print-certs` 로 확인.
5. **첫 release 빌드**: `scripts/local-build.ps1` 로 `:app:assembleRelease`, `:bench:assembleRelease`. 걸린 시간 기록.
6. **태블릿 무선 adb 페어링**: TB375FC 개발자 옵션 → 무선 디버깅 → 페어링 코드. 대표님이 화면 조작, Claude Code 는 `adb pair`/`adb connect` 안내·실행.
7. 두 기기에 `adb install -r` 로 덮어 설치(앱 삭제 금지). 실행해 서재가 그대로 있는지 확인.
8. **허용·금지 명령 목록** `.claude/settings.json` 을 만들어 대표님께 보여 드리고 승인받은 뒤 커밋:
