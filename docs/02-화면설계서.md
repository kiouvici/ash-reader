## 0. 읽는 법

- 화면 번호는 `S-xx`, 요구사항 번호는 `F-xx`/`N-xx`로 적는다.
- 와이어프레임은 휴대폰 세로(폭 360dp 기준)를 먼저 그리고, 태블릿 가로(짧은 변 600dp 이상, 가로)는 달라지는 점만 적는다.
- `[ ]`는 버튼, `( )`는 선택 칩·라디오, `[■]`/`[□]`는 켜짐/꺼짐 스위치, `▸`는 하위 화면으로 이동, `⋮`는 더보기 메뉴.
- 아이콘 이름은 Material Symbols 이름(예: `bookmark`)으로 적는다.

## 1. 디자인 원칙과 시각 방향

### 1.1 디자인 원칙 (5개)

| 번호 | 원칙 | 화면에서 지키는 방법 |
|---|---|---|
| P1 | **열면 바로 본문** | 외부에서 받은 파일은 중간 화면 없이 곧장 본문을 연다. 권한·설정은 꼭 필요한 순간에만 묻는다(알림 권한은 TTS 처음 쓸 때). 서재 첫 칸은 '이어 읽기'. |
| P2 | **본문이 주인공** | 읽기 화면은 기본 전체 화면, 메뉴는 가운데 탭으로만 나온다. 메뉴는 본문 위에 얹히고 본문을 밀어내지 않는다. |
| P3 | **보통의 이북 리더처럼** | 리디·밀리의 서재·문 리더 등에서 익숙한 배치(위: 뒤로·제목·책갈피 / 아래: 쪽 슬라이더·도구 5칸, 'Aa' 보기 설정)를 따른다. 새로운 조작을 만들지 않는다. |
| P4 | **쉬운 말, 되돌릴 수 있는 동작** | 기술 용어 대신 생활 말(예: 'MIME' → '파일 종류'). 삭제·초기화·복원은 확인을 받고, 서재에서 빼기는 '되돌리기' 스낵바를 준다. 원본 파일은 어떤 화면에서도 바뀌지 않는다(N-04). |
| P5 | **크게, 또렷하게** | 눌리는 곳은 최소 48×48dp, 글자 대비 4.5:1 이상, 색만으로 뜻을 전하지 않는다(형식 배지에 글자 병기). 시스템 글꼴 200%에서도 잘리지 않는다(N-08). |

### 1.2 시각 체계

**바탕: 머티리얼 3(Material You) 기반**, Jetpack Compose Material3 구성요소를 쓴다. 이유: 안드로이드 사용자에게 가장 친숙하고, 접근성(글꼴 배율·대비·TalkBack)이 기본으로 맞춰져 있으며, 휴대폰·태블릿 반응형 규칙(창 크기 등급)이 정해져 있다.

- **기기 배경화면 색 따르기(다이내믹 컬러)**: 잠정안은 '기본 끔, 설정에서 켤 수 있음'(대표님 결정 대기 2의 C안). 끈 상태에서는 아래 'ASH 잉크' 색을 쓴다. 형식 배지 색과 읽기 테마는 어느 안이든 고정이다.
- 앱 화면(서재·설정)의 밝음/어두움은 '시스템 따름' 기본. **읽기 테마(주간·세피아·야간)는 앱 화면 테마와 따로** 정한다.

#### 아이콘

- **Material Symbols Rounded**(Apache 2.0, 오픈소스 고지에 기재), 선 굵기 400, 채움은 켜진 상태에만(예: 책갈피 켜짐 = 채운 `bookmark`).
- 아이콘만 있는 버튼은 길게 누르면 이름 풍선(tooltip)이 나오고, TalkBack 설명(contentDescription)을 모두 단다.
- 읽기 화면 아래 도구줄은 **아이콘 + 글자 이름**을 함께 표시한다(비개발자 사용자 배려, P3).
- 앱 아이콘·일러스트는 부록 C(ChatGPT 제작).

#### 모양·움직임

- 모서리: 카드 12dp, 바텀시트 위쪽 28dp(M3 기본), 표지 썸네일 4dp(책 느낌).
- 표지 비율 2:3 고정, 표지가 다른 비율이면 가운데 맞춤 + 흐린 배경 채움.
- 움직임: M3 표준(메뉴 나타남 200ms, 시트 300ms). 시스템 '애니메이션 제거' 설정이면 메뉴·시트 애니메이션은 끄되, 쪽 넘김 효과는 사용자가 고른 대로 둔다(단, 처음 설치 시 기본값을 '슬라이드'로).

### 1.3 읽기 테마 (F-21·F-42·F-43)

| 테마 | 바탕 | 글자 | 대비 | 링크·강조 | 고정 쪽 문서 |
|---|---|---|---|---|---|
| 주간 | `#FFFFFF` | `#1F1F1F` | 16.5:1 | `#1F5FA8` | 원본 그대로 |
| 세피아 | `#F4ECD8` | `#4A3A2C` | 9.2:1 | `#8C5A2B` | 원본에 종이색 곱하기(그림 포함) |
| 야간 | `#121212` | `#CFCFCF` | 12.0:1 | `#9EC5F5` | 색 반전, '그림은 반전하지 않기' 기본 켬 |
| 사용자 테마 | 직접 지정 | 직접 지정 | 저장 시 4.5:1 미만이면 "글자가 잘 안 보일 수 있어요" 경고(저장은 허용) | — | 바탕·글자색으로 2색 변환 |

- 형광펜 색 4가지(노랑·초록·파랑·분홍)는 테마별로 반투명 값을 따로 정해 글자 대비 4.5:1을 지킨다(야간은 채도를 낮춘 색).
- 색온도 필터(F-42)는 테마 위에 덧씌우는 주황 막(강도 0~80%). 지정 시각 자동 켜기.
- 밝기는 앱 자체 밝기(창 밝기)로 조절하며 시스템 밝기는 바꾸지 않는다. 최저 밝기 아래로는 '추가 어둡게'(검은 막) 0~60%를 둔다.
- **테마 적용 방식(M-05)**: 이북류·eBook 보기는 글자색·바탕색을 바꿔 다시 그린다(그림은 반전하지 않음). 고정 쪽 문서(PDF·DjVu·HWP 원본·DOCX 구조 보존)만 색 반전·종이색 곱하기를 쓴다. 테마를 바꾸면 지금 쪽부터 먼저 다시 그리고, 나머지 쪽은 뒤에서 바꾼다(잠깐 깜박임 허용).
- **넘김 효과와 테마(M-03)**: 종이가 말릴 때 보이는 뒷면은 지금 테마의 바탕색(야간 `#121212`, 세피아 `#F4ECD8`, 사용자 테마는 그 바탕색)으로 섞는다. 야간에는 그림자 강도를 절반으로 낮춘다. 흰 뒷면이 번쩍이지 않아야 한다.

#### S-17 서재 폴더 (7차 목업 `docs/목업-7차/LibraryFolders.dc.html`)

```
┌──────────────────────────────────────┐
│ [←] 서재 폴더                         │
│ 고른 폴더 안의 책을 서재에 모아 보여 줘요. │

│ └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘ │

- **폴더 추가**: 시스템 폴더 고르기(`ACTION_OPEN_DOCUMENT_TREE`), 처음 위치 Download. 고른 폴더는 읽기 권한을 오래 쥔다(`takePersistableUriPermission`). 여러 개 고를 수 있다.
  - Android 11+ 에서 '모든 파일 접근'이 없으면 Download 자체는 고를 수 없어 "Android 11부터는 Download 폴더 자체는 고를 수 없어요. 그 안의 폴더를 골라 주세요." 한 줄. '모든 파일 접근'이 있으면 [Download 폴더 바로 추가]는 경로로 바로 넣는다.
- **하위 폴더도 포함**(폴더마다, 기본 켬): 끄면 그 폴더 바로 안의 파일만 모은다.
- **겹친 폴더**: 이미 고른 폴더('하위 폴더도 포함') 안의 폴더를 고르면 더하지 않고 스낵바 "이미 '○○'에 들어 있는 폴더예요". 같은 폴더는 "이미 고른 폴더예요". 나중에 더 위 폴더를 고르면 안쪽 폴더 카드에 "'○○'에 함께 들어 있어요"가 붙고 따로 훑지 않는다 — 같은 책을 두 번 세지 않는다('책 N권'은 서로 다른 책 수).
- **빼기**: 바로 목록에서 빠지고 스낵바 "서재에서만 뺐어요. 기기의 파일은 그대로예요. [되돌리기]"(약 10초). 되돌릴 시간이 지나면 폴더 읽기 권한을 놓는다. 그 폴더의 책은 서재에서 숨지만 읽은 위치·책갈피는 문서 식별(F-63)로 남아, 같은 폴더를 다시 더하면 이어진다.
- **찾을 수 없는 폴더**(SD 카드를 뺌·권한이 풀림·폴더가 지워짐): 회색 카드 + "폴더를 찾을 수 없어요" + [다시 고르기](그 자리에서 폴더 고르기, '하위 폴더도 포함'은 그대로). 그 안의 책은 지우지 않고 서재에서 '열 수 없음'으로 보인다(S-10).
- **빈 상태**: 폴더 그림 + "아직 고른 폴더가 없어요" + [폴더 추가].
- **옛 판의 빼는 폴더**: 예전에 고른 '빼는 폴더'가 있으면 목록 아래 '빼는 폴더' 묶음에 보이고 [풀기]만 있다(새로 고르는 단추는 없음 — 대신 '하위 폴더도 포함'을 끈다).
- **360dp 휴대폰**: 폴더 이름 2줄까지, 경로는 한 줄 가운데 줄임(앞의 볼륨 이름과 끝의 폴더 이름이 보이게). 보조 글자 14sp, 색 #5F6368.
- **태블릿 가로**(폭 840dp 이상): 왼쪽 폴더 목록, 오른쪽 '서재에 있는 책' 요약과 [서재로 가기](S-51 두 칸과 같은 기준).
- 접근성: 카드마다 [빼기]에 "○○ 폴더 빼기", 경로는 줄이지 않은 전체를 읽어 준다. '하위 폴더도 포함'은 체크박스 역할.

- 탭 영역은 4.1, 제스처는 4.2.
- 태블릿 가로: 두 쪽 펼침(가운데 접힘 그림자 약하게), 정보줄은 각 쪽 아래 또는 전체 아래 한 줄(설정).

**쪽 수 계산 중 상태 (M-01, 리플로 문서)**

리플로 문서(이북류·eBook 보기)는 열자마자 지금 장만 배치하고, 전체 쪽 수는 뒤에서 센다. 계산이 끝나기 전에는 쪽 수 대신 아래처럼 보인다.

| 자리 | 계산 중 | 계산 끝 |
|---|---|---|
| 정보줄 진행 | `35%` | `35% · 74/210쪽`(쪽 수 켠 경우) |
| 정보줄 이번 장 | `이 장 3/12쪽` | `이 장 3쪽 남음` |
| 정보줄 남은 시간 | 표시 안 함 | `약 2시간` |
| 메뉴 쪽 표시(S-21) | `35% · 이 장 3/12쪽` + 작은 원형 진행 표시 | `74 / 210쪽 · 35%` |
| 슬라이더 | 진행률(0~100%) 기준으로 움직임, 말풍선은 장 이름 + % | 쪽 기준 |
| 다음 권 확인(S-45) | 마지막 장의 마지막 쪽에서 판정(쪽 수 없이도 동작) | 같음 |

- 계산이 끝나면 숫자만 조용히 바뀐다(스낵바 없음). 원형 진행 표시를 누르면 "전체 쪽 수를 세는 중이에요" 풍선.
- 보기 설정·회전·펼침 전환으로 다시 배치하면 다시 '계산 중' 상태로 돌아간다.

**다시 배치하는 중 (M-02, 엔진 교차 검토)**

- 글자 크기·글꼴·간격·여백 변경, 화면 회전, 태블릿 한 쪽↔두 쪽 펼침 전환 때 리플로 문서는 쪽을 다시 나눈다.
- 지금 장을 다시 배치하는 동안(0.3초 넘을 때만) 본문 위 가운데에 작은 알약 표시 "다시 배치하는 중…"(원형 진행 + 글자). 본문은 이전 상태를 흐리게 두고 끝나면 바뀐다. 읽던 문장 위치는 유지한다.
- 회전·펼침 전환으로 쪽 수가 바뀐 첫 1회에만 스낵바: "쪽 수는 화면 크기와 글자 설정에 따라 달라져요. 읽던 곳은 그대로예요."
- 책갈피·형광펜 목록(S-22)의 쪽 번호도 다시 계산되며, 계산 전에는 장 이름만 보인다.

**넘기는 동안 (M-03)**

- 형광펜·검색 강조·듣기 강조는 쪽과 함께 말려 넘어간다(따로 떠 있지 않음).
- 정보줄은 넘김 효과와 상관없이 제자리에 고정되고, 넘김이 끝나면 값이 바뀐다.

**HWP 원본 쪽 준비 중 (M-06)**

- HWP 원본은 앞 3쪽을 미리 그려 둔다. 그래도 다음 쪽이 준비되지 않았으면 테마 바탕색의 빈 종이로 넘기고, 쪽 가운데에 원형 진행 표시와 "쪽을 그리는 중…"을 둔다. 준비되면 0.15초 서서히 나타난다.
- 같은 방식을 solid CBR의 아직 풀리지 않은 쪽에도 쓴다(S-30·S-41 참고).

#### S-30 쪽 미리보기 / 쪽 목록 그리드

- 슬라이더를 끄는 동안 손가락 위에 축소 그림(고정 쪽·만화) 또는 장 이름+쪽 번호(이북류) 말풍선.
- **축소 그림이 아직 없을 때(엔진 교차 검토)**: 끄는 속도가 빨라 축소 그림이 준비되지 않으면 같은 크기의 회색 종이 틀 안에 쪽 번호만 크게 보이고, 손가락이 멈추면(0.2초) 축소 그림을 그려 바꿔 끼운다. HWP 원본·DOCX 구조 보존은 쪽 번호 + 그 쪽 첫 문단 앞부분(글자) 말풍선으로 대신할 수 있다. solid CBR의 아직 풀리지 않은 쪽은 쪽 번호 + "아직 준비 중" 꼬리표.
- 쪽 목록 그리드에서 아직 그리지 못한 칸은 회색 틀 + 쪽 번호로 먼저 채우고, 화면에 보이는 칸부터 그린다. solid CBR은 풀린 쪽까지 채워지고, 나머지는 "준비 중" 틀.
- 쪽 목록 그리드(만화 '쪽 목록' 버튼, 고정 쪽은 ⋮): 전체 화면, 휴대폰 3열/태블릿 가로 6열, 현재 쪽 테두리 강조, 책갈피 쪽 모서리 표시. 오→왼 책은 격자도 오른쪽부터 채운다.

│ [ eBook 보기로 바꾸기 ]  ← 글자 크기를 키워 읽기          │ F-25
```

- 도구줄 'eBook 보기 전환' 버튼은 지금 상태를 보여 주는 두 칸 토글: `[원본 | eBook]`. eBook 보기로 바꾸면 도구줄이 이북류(Aa 포함)로 바뀐다.
- **전환 위치(M-13)**: HWP·HWPX·DOCX는 같은 문단으로 이어진다. 글자 있는 PDF는 문단을 정확히 맞출 수 없어 **"대략 같은 위치"** 로 이어지며, 처음 전환할 때 1회 스낵바: "PDF는 비슷한 위치로 이어져요. 앞뒤를 조금 넘겨 확인해 주세요."
- eBook 보기가 안 되는 문서(스캔 PDF·DjVu)에서는 버튼을 숨긴다(흐리게가 아니라 숨김 — 부록 A '–').
- **스캔 판정 전(M-13)**: PDF는 열린 뒤 첫 3쪽의 글자 수로 '글자 있음/스캔'을 판정한다. 판정이 끝나기 전에는 도구줄 4번 칸을 **비워 둔다**(버튼 없음, 자리만 유지해 나머지 버튼이 움직이지 않게). 판정 후 'eBook' 또는 '쪽 목록'이 0.2초 서서히 나타난다. 같은 문서를 다시 열면 저장된 판정으로 바로 보인다.
- HWP 원본 보기 실패 시 자동 전환(F-28) → S-44 스낵바. 원본 보기 버튼은 남겨 두되 누르면 "원본 모양으로 보여 드리지 못했어요. eBook 보기로 읽어 주세요." 
- 확대 상태 표시: 오른쪽 아래 작은 배율 표시 "200%"(2초 후 사라짐).

#### S-33 만화 설정

바텀시트, 위 탭 3개: **넘김 / 보기 / 화질**. 이 책에만 기억(F-48, F-57), 시트 아래 [모든 만화 기본값으로].

```
[넘김] 탭
│ 읽는 방향  (왼→오)(오→왼)(위→아래 · 웹툰)  │ F-48 (자동 인식 시 '자동: 오→왼' 꼬리표, F-49)
│ 두 쪽 보기 (자동)(한 쪽)(두 쪽)             │
│ 첫 쪽 단독 [■]   [짝 한 쪽 밀기][되돌리기]   │ F-50
│ 가로로 긴 쪽 (반으로 나눔)(회전)(그대로)     │ F-51 (한 쪽 모드일 때만)
│ ── 칸 단위 보기 ──                          │ F-72

│ 밝기 ━━●━━ 대비 ━━●━━ 감마 ━━●━━ [초기화]  │ F-57
│ 흑백 [□]  색 반전 [□]                       │
│ 확대 방식 (빠름)(고품질)  선명하게 ━●━━━    │ F-56

[화질] 탭 (7차: 스위치를 나눔 단추로)
│ AI 화질 향상                                 │ F-73 (책마다, 기본 끔)
│ 작은 그림을 2배로 선명하게 키워요.           │
│ [ 원본 | AI 향상 | 전후 비교 ]               │ ← 48dp 이상 나눔 단추
│ (칸 보기·웹툰일 때) 칸 보기·웹툰에서는 비교할 수 없어요 │ ← '전후 비교' 흐리게
│ 처리한 쪽: 12 / 210   저장 공간 120MB / 1GB  │

**전후 비교** (7차 목업 `docs/목업-7차/AiCompare.dc.html`)

- [화질] 탭에서 '전후 비교'를 고르면 시트가 닫히고 비교 화면이 **도구 막대 자리를 차지**한다: 위 [←] "전후 비교 · 12 / 186쪽" [◀][▶](쪽 바꾸기는 이 단추로만).
- 쪽 한 장을 왼쪽 원본 / 오른쪽 AI 로 나눠 보이고, 나누는 선은 노랑 3dp + 어두운 1dp 테두리. **노란 손잡이(48dp, 1dp 어두운 테두리)만** 끌어서 선을 옮긴다. 비교 중에는 쪽 밀어 넘기기를 막는다. 끌기 어려우면 [◀ 원본 더 보기][AI 더 보기 ▶](48dp).
- 아래 "노란 손잡이를 좌우로 끌어서 비교해요 · 왼쪽 원본 / 오른쪽 AI" + [원본 | AI 향상 | 전후 비교](원본·AI 향상을 고르면 그 방식으로 비교를 끝냄). 뒤로 가기 = 비교 끝(보던 쪽으로).
- 아직 처리하지 않은 쪽: 비교를 흐리게 + "이 쪽은 아직 처리 중이에요" + 진행 표시. 처리하면 바로 비교가 보인다.
- 건너뛴 쪽(이미 화면 해상도 이상): "이 쪽은 이미 선명해서 처리하지 않았어요".
- 칸 보기·웹툰: '전후 비교'를 흐리게 하고 "칸 보기·웹툰에서는 비교할 수 없어요".
- 태블릿 두 쪽 펼침: 지금 쪽(펼침의 첫 쪽) 하나만 비교한다.
- 기기 성능 부족: 나눔 단추를 숨기고 아래 표의 이유 문구(기존과 같음).
- 처음 'AI 향상'이나 '전후 비교'를 고르면 S-36 확인창을 먼저 띄운다.

**AI 화질 향상을 숨기는 이유별 문구(엔진 교차 검토)**

| 이유 | [화질] 탭에 보이는 문구 | 다시 보이는 조건 |
|---|---|---|
| 메모리 부족(RAM 3GB 미만) | 이 기기는 메모리가 부족해서 AI 화질 향상을 쓸 수 없어요. | 없음 |
| 그래픽 처리 미지원 + 기기 속도 느림(예상 쪽당 15초 초과) | 이 기기에서는 처리가 너무 느려서 AI 화질 향상을 쓸 수 없어요. | 없음 |
| 발열·배터리(일시) | 기기가 뜨겁거나 배터리가 적어서 잠시 멈췄어요. 식거나 충전하면 다시 시작해요. | 온도·배터리 회복 시 자동 재개 |
| 판정 중(처음 [화질] 탭을 열 때) | 이 기기에서 쓸 수 있는지 확인하는 중이에요… (약 10초) | 판정 끝 |

- 그래픽 처리 없이 CPU로만 돌지만 기준(15초)은 넘지 않는 기기: 나눔 단추는 보이되 아래에 "이 기기에서는 쪽마다 시간이 조금 걸려요(약 ○초)."

- 칸 단위 보기 스위치는 도구줄 '칸' 버튼으로도 바로 켜고 끈다(켜짐 = 채운 아이콘 + "칸 켜짐" 스낵바).
- 웹툰(위→아래) 고르면 두 쪽 보기·넘김 효과·칸 단위 보기 항목을 흐리게 하고 "웹툰 보기에서는 쓰지 않아요" 한 줄.
- 태블릿 가로: 오른쪽 측면 시트, 바꾸는 즉시 펼침 화면에 반영.

#### S-34 칸 단위 보기 상태

- 눌러서 확대(기본): 쪽 전체 → 칸을 누름 → 그 칸이 화면에 맞게 확대(확대 이동 애니메이션 250ms). 위 가운데에 작은 표시 "칸 3 / 7". 넘기면 다음 칸, 마지막 칸 다음은 다음 쪽(쪽이 바뀔 때만 넘김 효과).
- 자동 순서: 쪽을 열면 첫 칸부터 확대. 넘김 = 다음 칸. 칸을 누르면 쪽 전체 보기와 칸 보기 사이를 오감.
- 칸을 못 찾은 쪽: 쪽 전체로 보이고, 위 표시가 "이 쪽은 칸을 찾지 못했어요"(1.5초).
- 처음 칸을 인식하는 쪽에는 작은 원형 진행 표시(오른쪽 아래), 사용자가 기다리지 않게 쪽은 먼저 보여 준다. 앞쪽 2쪽은 미리 인식해 둔다.
- 인식이 끝나기 전에 칸 자리를 누르면: 누른 지점에 옅은 원 반응 → 1초 안에 결과가 나오면 그 칸을 확대, 넘으면 일반 탭 영역 동작으로 처리.
- 탭 규칙은 4.3(대기 시간·위 띠는 실험 ③ 후 확정, M-12).

#### S-35 웹툰 보기 제안

- 확인창: "세로로 긴 그림이 많은 만화예요. 웹툰처럼 위아래로 내려 읽을까요?" [웹툰으로 보기] [그대로 보기]. '다시 묻지 않기' 없음(책마다 처음 1회만 묻기 때문, 선택은 책마다 기억).

#### S-36 AI 화질 향상 안내·진행

- 처음 켤 때(S-33 [화질] 'AI 향상'·'전후 비교'를 처음 고를 때) 확인창: "AI 화질 향상을 켤까요? 처리하는 동안 배터리를 더 쓰고 기기가 따뜻해질 수 있어요. 처리한 그림은 최대 1GB까지 저장해 둡니다." [켜기][취소]
- 처리 중: 오른쪽 위 작은 `auto_awesome` 아이콘 + 회전(메뉴 숨김 상태에서도 아주 작게, 끌 수 있음). 처리된 쪽으로 바꿔 끼울 때 0.2초 서서히 바뀜.
- 자동 멈춤: 스낵바 "기기가 뜨거워져서 화질 향상을 잠시 멈췄어요."
- 기기 성능 부족: 스위치 자체를 숨기고 그 자리에 이유별 문구(S-33 표).
- 쪽을 넘기거나 칸을 확대하는 동안에는 처리를 잠시 쉬어 넘김이 버벅이지 않게 한다(사용자에게 따로 알리지 않음). 종이 넘김 애니메이션 신호는 EPUB 그림 AI(D-021)에도 같이 쓴다.

#### S-39 표 크게 보기 (M-04, eBook 보기)

eBook 보기(HWP·HWPX·DOCX eBook, DOC, RTF·EPUB의 표)에서 표는 쪽 폭에 맞춰 줄여 보인다. 글자가 본문보다 작아진 표(본문 글자의 80% 미만)에는 표 오른쪽 위에 작은 `open_in_full` 아이콘 + "크게"를 붙인다. 표를 누르거나 아이콘을 누르면 이 창이 열린다.

```
┌────────────────────────────────────┐
│ [✕] 표 크게 보기        [⟳ 가로로] │ ← 가로로: 이 창만 가로 화면으로 돌림
├────────────────────────────────────┤
│ ┌──────┬──────┬──────┬──────┬──  │
│ │ 구분 │ 1월  │ 2월  │ 3월  │ 4…  │ ← 원래 글자 크기로 그림. 두 손가락 확대·축소,
│ ├──────┼──────┼──────┼──────┼──  │   한 손가락 상하좌우 이동(관성)
│ │ 인건비│ 12.3 │ 12.3 │ 13.0 │ …  │
│ …                                  │
├────────────────────────────────────┤
│ 표 3 / 7          [◀ 이전 표][다음 표 ▶] │
└────────────────────────────────────┘
```

- 읽기 테마 색을 그대로 따른다. 처음 열 때 표 왼쪽 위가 보이고, 폭이 화면보다 넓으면 오른쪽 가장자리에 그림자로 "옆으로 더 있음"을 알린다.
- 표 안 글자도 길게 눌러 복사할 수 있다(형광펜은 본문에서만).
- 뒤로 가기·✕ = 읽던 쪽으로 돌아감(위치 그대로).
- 태블릿 가로: 전체 화면 대신 본문 위 큰 창(화면 90%).
- 형식별 범위: eBook 보기·이북류 전용. 고정 쪽 문서(원본 보기)는 이미 확대·이동이 되므로 쓰지 않는다.

### 3.4 열기 관련

#### S-40 외부에서 연 파일 (한 번만 보기)

```
┌────────────────────────────────────┐
│ ⓘ 한 번만 보는 중이에요.  [서재에 추가] │ ← 위 띠(메뉴 숨김 상태에서도 첫 3초 표시 후 접힘)
├────────────────────────────────────┤
│        (본문 — 읽기 화면과 같음)     │
```

- 띠는 3초 뒤 접히고, 메뉴를 열면 위 바 아래에 다시 보인다.
- 메뉴 표시 상태의 위 바: [←](보낸 앱으로) 제목 … ⋮에 '서재에 추가' 포함.
- [서재에 추가] → 확인 없이 바로 실행, 스낵바 "서재에 추가했어요. 이제 읽던 곳을 기억해요." 띠는 사라짐.
- 같은 문서가 이미 서재에 있으면(F-63) 띠 대신: "서재의 같은 문서로 이어서 읽어요 · 42쪽" (한 번만 보기 아님).
- 닫을 때 확인창 없음(P1). 기억하지 않는다는 사실은 띠로만 알린다.
- 공유(ACTION_SEND)로 여러 파일이 들어오면 S-46과 같은 목록 시트로 고르게 한다.

#### S-41 여는 중

- 2초 안에 열리면 아무것도 안 보인다(N-01). 2초 넘으면 가운데 원형 진행 + "여는 중… (한글 문서는 조금 걸릴 수 있어요)" + [취소].
- HWP 원본 렌더가 10초를 넘기면 자동 전환(F-28).
- **solid CBR(N-02·N-09 예외)**: 첫 쪽이 풀리면 바로 보여 주고, 나머지는 뒤에서 앞에서부터 차례로 푼다. 읽기 화면 위 가장자리에 얇은 진행 막대(2dp, 메뉴 숨김 상태에서도 보임) — 다 풀리면 사라진다. 아직 풀리지 않은 쪽으로 가면 S-20 'HWP 원본 쪽 준비 중'과 같은 빈 종이 + "쪽 준비 중… 120 / 210" + [멈추기]를 보이고, 풀리면 바로 그 쪽을 보여 준다. [멈추기]를 누르면 풀린 쪽까지만 볼 수 있고 문서 정보에 "일부만 준비됨"이 남는다.

#### S-42 암호 입력

```
┌──────────────────────────────┐
│ 🔒 암호가 걸린 문서예요        │
│ 2025년 인사기록.hwp            │
│ ┌──────────────────────┐ [👁] │
│ │ 암호                  │      │
│ └──────────────────────┘      │
│ 입력한 암호는 저장하지 않아요. │
│                [취소] [열기]  │
└──────────────────────────────┘
```

- 틀리면 입력창 아래 빨간 글: "암호가 맞지 않아요. 다시 입력해 주세요." (입력값 유지, 전체 선택)
- 암호 문서인데 앱이 열 수 없는 방식이면(HWP 일부): S-43 "이 암호 방식은 아직 열 수 없어요."
- **암호 DOCX(M-08)**: 실험 ②에서 해제가 되면 이 창을 그대로 쓴다. 안 되면 암호 입력창을 띄우지 않고 바로 S-43 "암호가 걸린 Word 문서는 아직 열 수 없어요"(5.2)로 안내한다. 암호를 받은 뒤에야 안 된다는 것을 알리는 일이 없게 한다.
- 키보드는 자동으로 열고, 엔터 = 열기.

│     이 파일을 열 수 없어요           │
│  파일이 손상되었거나 일부만 받아진   │
│  것 같아요.                          │
│                                    │
│  ▸ 해 볼 수 있는 일                  │
│   • 파일을 다시 받아 열어 보세요.    │
│   • 보낸 분께 PDF로 보내 달라고 해   │
│     보세요.                          │
│                                    │
│   [ 다른 앱으로 열기 ]  [ 닫기 ]     │
│   자세한 정보 ▾ (파일 이름, 크기,     │
│   알아낸 형식, 오류 번호 E-HWP-03)   │
└────────────────────────────────────┘
```

- 원인별 문구는 5장 표. '자세한 정보'에는 기술 정보를 넣되 기본은 접힘.
- **서점 보호 책(M-07)**: EPUB(서점 보호 표시 파일이 든 것)·MOBI·AZW3에 서점 보호가 걸려 있으면 같은 틀에 오류 그림 대신 책 그림, 제목 "서점 보호가 걸린 책이에요", 버튼 [내 서점 앱 열기](서점 바로가기 줄의 첫 앱, 등록 앱이 없으면 S-15) [닫기]. '해 볼 수 있는 일'은 "구매한 서점의 앱에서 읽어 주세요." 한 줄.
- 외부에서 연 파일이면 [닫기] = 보낸 앱으로.

#### S-44 자동 전환·가벼운 안내 (스낵바)

- 아래에서 올라오는 한 줄 + 선택 버튼 1개, 6초 표시(접근성 설정의 '반응 시간' 따름). 예: "원본 모양으로 열기 어려워서 eBook 보기로 보여 드려요. [원본으로 다시 시도]"

#### S-45 다음 권 확인창

```
┌──────────────────────────────┐
│ 마지막 쪽이에요                │
│ [다음 권 표지]  원피스 5권     │
│                 CBZ · 새 문서  │
│ [■] 4권을 '다 읽음'으로 표시   │
│           [닫기] [5권 열기]    │
└──────────────────────────────┘
```

- 마지막 쪽에서 한 번 더 넘길 때 뜬다. 서재 문서에만(F-61). 다음 권이 없으면 스낵바 "마지막 쪽이에요. [다 읽음으로 표시]".
- '다 읽음 표시' 체크는 기본 켬(사용자가 끄면 다음부터 끈 상태 기억).

#### S-46 압축 파일 안 고르기 (ZIP)

- 바텀시트: "압축 파일 안에 읽을 수 있는 파일이 3개 있어요" + 파일 목록(배지 + 이름) → 누르면 열기. 1개뿐이면 시트 없이 바로 연다. 0개면 S-43 "이 압축 파일 안에는 읽을 수 있는 파일이 없어요."

#### S-52 오픈소스 고지

- 목록: 라이브러리·글꼴·아이콘·AI 모델 이름 / 라이선스 이름(MIT, GPL-3.0, AGPL-3.0, OFL-1.1, Apache-2.0 …). 누르면 전문.
- 맨 위 카드(D-001): "이 앱에는 GPL·AGPL 라이선스 프로그램이 들어 있어요. 이 앱을 받은 분은 전체 소스 코드를 요청할 수 있어요. 요청: (연락처는 PM 확정 후 기재)"
- AI 모델(F-72·F-73)은 코드와 가중치 라이선스를 따로 적는다.

#### S-53 백업·복원

```
│ 백업 만들기                              │
│ 읽던 위치·책갈피·형광펜·메모·설정·독서 기록을 │
│ 파일 하나로 저장해요. (책 파일은 들어가지 않아요) │
│ 내 글꼴도 넣기 [■]  (내 글꼴 2개 · 12MB)  │  ← 내 글꼴이 있을 때만 보임(M-11)
│ [ 백업 파일 만들기 ]  → 저장 위치 고르기  │  기본 이름: ASH백업_2026-10-21.ashbak
│                                          │  (같은 날 두 번째부터 ASH백업_2026-10-21_2.ashbak)
│ 마지막 백업: 2026-10-01                   │
│ ─────────────────────────────────────── │
│ 백업에서 되살리기                         │
│ [ 백업 가져오기 ] ─▶ 백업 가져오기 화면(아래) │  ← 7차: '백업 파일 고르기'를 바꿈
```

**백업 가져오기** (7차 목업 `docs/목업-7차/BackupImport.dc.html` — 예전 '백업 파일 고르기'(파일 하나 고르기)를 바꾼다)

```
┌──────────────────────────────────────┐
│ [←] 백업 가져오기                      │
│ ┌──────────────────────────────────┐ │
│ │ 📁 찾는 폴더                [폴더 바꾸기] │ ← 48dp, 마지막 폴더 기억
│ │    Download/ASH Reader 백업        │ │    (처음 권장 위치)
│ └──────────────────────────────────┘ │
│ 이 폴더의 백업 파일 3개 · 최신 순       │
│ ┌──────────────────────────────────┐ │
│ │ (●) 2026년 10월 23일 오후 6:02 [가장 최근 백업] │
│ │     책 128권 · 책갈피 340 · 메모 52  │ │ ← 백업 머리(앞 4KB)의 요약만 읽음
│ │     ASH백업_2026-10-23.ashbak · 1.2MB │ │
│ └──────────────────────────────────┘ │
│ ( ) 2026년 10월 20일 …                 │
│ 백업 파일(.ashbak)만 보여요. 다른 파일은 숨겨요. │
├──────────────────────────────────────┤
│ [ 합치기        ][ 모두 바꾸기       ] │ ← 56dp 카드 2개, 기본 합치기
│   지금 기록은 두고 더하기  지금 기록을 백업으로 바꾸기 │
│ [            가져오기             ]   │ ← 52dp
└──────────────────────────────────────┘
```

- 폴더는 시스템 폴더 고르기(SAF)로 고르고 기억한다(기기에만, 백업에는 넣지 않음). 처음 권장 위치는 `Download/ASH Reader 백업`('모든 파일 접근'이 있으면 고르지 않아도 그 폴더를 바로 본다).
- 목록은 백업 파일만(.ashbak, 그리고 예전 이름 `ASH-백업-YYYYMMDD-HHMM.json`) 최신 순. 줄마다 날짜(백업한 시각), 내용 요약(책·책갈피·메모 — 메모는 메모 + 메모 붙은 형광펜), 파일 이름·크기. 맨 위 정상 백업에 '가장 최근 백업' 표시, 처음엔 그것이 골라져 있다.
- 요약은 백업 파일 맨 앞의 `summary`(내보낼 때 씀)만 읽어 빠르다. 요약이 없는 예전 백업은 8MB 이하면 한 번 읽어 세고, 크면 "내용 요약 없음(예전 백업)".
- 빈 폴더: "이 폴더에는 백업 파일이 없어요" + [폴더 바꾸기], [가져오기]는 흐리게. 폴더를 읽을 수 없으면(권한 풀림) "폴더를 읽을 수 없어요. 폴더를 다시 골라 주세요." + [폴더 바꾸기].
- 백업이 아니거나 손상된 파일·새 판 백업은 줄에 기존 S-53 문구("ASH Reader 백업 파일이 아니에요." / "더 새 판에서 만든 백업이에요. 앱을 업데이트한 뒤 가져와 주세요.")를 빨간 글자로 보이고 고를 수 없다.
- '모두 바꾸기'로 [가져오기]를 누르면 확인창 "지금 기록이 모두 사라지고 백업 내용으로 바뀌어요. 바꿀까요?" [모두 바꾸기](빨간 단추)[취소]. 바꾸면 책갈피·메모·형광펜·독서 기록을 지우고 읽은 위치·상태·즐겨찾기를 처음으로 한 뒤 백업 내용으로 채운다(서재의 책 목록과 파일은 그대로).
- 끝나면 설정으로 돌아가 결과 스낵바(합친 개수, 이 기기에 없는 책 수).
- 태블릿 가로: 왼쪽 파일 목록, 오른쪽 가져오기 방식과 [가져오기].
- 백업 이름(M-11): `ASH백업_YYYY-MM-DD.ashbak`, 같은 날 기억한 폴더에 이미 있으면 `ASH백업_YYYY-MM-DD_2.ashbak`. 저장 위치 고르기는 기억한 백업 폴더에서 시작한다.

- '합치기'(기본)는 같은 문서의 기록은 더 최근 것을 남긴다. '모두 바꾸기'는 2차 확인 "지금 기록이 모두 사라지고 백업 내용으로 바뀌어요." (M-11: 둘 다 지원)
- 백업에 글꼴이 들어 있으면 미리보기에 "내 글꼴 2개"가 함께 보이고, 되살릴 때 같은 이름 글꼴은 덮어쓰지 않는다.
- 새 버전 앱이 만든 백업을 옛 버전에서 고르면: "더 새 버전의 ASH Reader에서 만든 백업이에요. 앱을 업데이트한 뒤 되살려 주세요."
- 다른 기기에서 만든 백업도 파일 식별값(F-63)으로 이어지므로 "같은 파일이 이 기기에 있으면 이어서 읽을 수 있어요" 안내.
- AI 화질 캐시는 백업하지 않음(F-73) — 문구에 따로 적지 않는다.

#### S-54 형광펜·메모 내보내기

- 바텀시트: 형식 (텍스트 .txt)(마크다운 .md) / 범위 (이 책)(모든 책) / [파일로 저장] [공유하기].

#### S-55 사전 앱 없음 안내

- 확인창: "말글사전이 설치되어 있지 않아요. 말글사전 APK를 설치하세요. 지금은 다른 사전 앱으로 찾아볼까요?" [다른 사전 앱 고르기] [닫기]. 고를 앱도 없으면 "단어를 찾아볼 사전 앱이 없어요."

## 4. 조작 체계

### 4.1 탭 영역 (F-64) 기본값

| 방식 | 휴대폰 세로 | 태블릿 가로(두 쪽) | 비고 |
|---|---|---|---|
| **좌우(기본)** | 왼쪽 30% 이전 / 가운데 40% 메뉴 / 오른쪽 30% 다음 | 같은 비율(화면 전체 기준) | 모든 형식 기본 |
| L자 | 위 25% 띠 + 왼쪽 30% = 이전 / 가운데 상자(가로 40%×세로 40%) = 메뉴 / 나머지 = 다음 | 같음 | 한 손 엄지용 |
| 어디든 다음 | 가운데 상자(40%×40%) = 메뉴 / 나머지 전부 = 다음. 이전은 스와이프·볼륨 키 | 같음 | |
| 내 방식 | 3×3 칸마다 (이전)(다음)(메뉴)(없음) 지정 | 같음 | 편집기: 3×3 격자를 눌러 순환 |

- 오→왼 책(만화 F-48, 자동 인식 F-49 포함): 이전/다음 좌우가 자동으로 바뀐다(왼쪽 = 다음).
- 왼손잡이: 좌우 반전(오→왼과 겹치면 두 번 뒤집혀 원래대로가 되므로, 실제 적용 결과를 S-31로 다시 보여 준다).
- 스크롤 보기·웹툰: 왼쪽/오른쪽 대신 **위 30% = 위로 한 화면, 아래 30% = 아래로 한 화면**(화면 높이 90% 이동, 10% 겹침).

### 4.2 제스처 표

| 동작 | 이북류(쪽 넘김) | 스크롤·웹툰 | 고정 쪽·만화(맞춤 상태) | 고정 쪽·만화(확대 상태) |
|---|---|---|---|---|
| 한 번 탭 | 탭 영역(4.1) | 탭 영역(위/아래) | 탭 영역(가장자리는 즉시, 가운데는 4.4 지연) | 가장자리 = 넘김, 가운데 = 메뉴 |
| 두 번 탭 | 없음(즉시 반응 위해) | 없음 | 2배 확대(가운데 영역에서만) | 맞춤으로 복귀 |
| 좌우 밀기 | 쪽 넘김(효과 따라 종이가 손가락을 따라감) | 없음 | 쪽 넘김 | 화면 이동(넘기지 않음, F-08) |
| 위아래 밀기 | 없음 | 스크롤 | 없음 | 화면 이동 |
| 두 손가락 벌리기/모으기 | 기본 없음. 설정에서 켜면 글자 크기 조절(벌리는 동안 크기 숫자만, 손 떼면 적용 — M-02) | 웹툰: 확대 | 확대·축소 | 확대·축소 |
| 길게 누르기 | 글자 선택(S-28) | 글자 선택 / 웹툰: F-59 메뉴 | 글자 있으면 선택, 만화는 F-59 메뉴 | 같음 |
| 왼쪽 가장자리 위아래 밀기 | 밝기(F-65) | 밝기 | 밝기 | 밝기 |
| 뒤로 가기 | 메뉴/시트 닫기 → 서재 | 같음 | 같음 | 같음(먼저 맞춤으로 되돌리지 않음) |

- **가장자리 밝기(F-65)**: 왼쪽 가장자리 폭 32dp, 화면 세로 가운데 200dp 구간만 시스템 제스처 제외 영역으로 지정한다. 이 구간에서 세로 이동이 가로 이동의 2배 이상이면 밝기, 아니면 일반 동작. 200dp 밖 가장자리는 시스템 뒤로 가기가 그대로 동작한다. 밝기를 바꾸는 동안 가운데에 "밝기 60%" 큰 표시.
- 종이책 넘김 효과에서 손가락을 중간에 놓으면 넘어간 정도 50% 기준으로 넘기거나 되돌린다.

### 4.3 칸 단위 보기 탭 규칙 (F-72)

> **잠정안 — 실험 ③ 후 확정(M-12)**: 아래 대기 시간 250ms와 '위 가장자리 띠 = 메뉴' 위치는 실험 ③에서 200/250/300ms 체감 비교와 몰입 모드의 상태 표시줄 내리기 충돌 확인 후 정한다. 위 띠 위치는 대표님 결정 대기 3의 결과도 따른다. 확정되면 이 표와 S-31 안내 그림을 고친다.

칸 단위 보기가 **켜져 있을 때만** 아래 순서로 판정한다.

| 순서 | 눌린 곳 | 한 번 탭(250ms 안에 두 번째 탭 없음) | 두 번 탭 |
|---|---|---|---|
| 1 | 화면 위 가장자리 띠(높이 12%) | **메뉴 표시/숨김** | 없음 |
| 2 | 좌우 가장자리(각 15%, 칸 위여도) | 이전/다음 칸(오→왼이면 반대) — **즉시 처리** | (두 번 넘김) |
| 3 | 칸 위 | 눌러서 확대: 쪽 전체 → 그 칸 확대 / 칸 확대 → 쪽 전체 · 자동 순서: 칸 보기 ↔ 쪽 전체 | 그 지점 2배 확대(F-55), 다시 두 번 탭 = 직전 상태로 |
| 4 | 칸 밖 여백 | 기존 탭 영역(F-64) 동작 | 가운데면 2배 확대 |

- 칸 단위 보기가 켜지면 좌우 가장자리 탭 폭을 30%→15%로 좁혀 칸을 누를 공간을 넓힌다(S-31로 1회 안내: "칸을 누르면 크게 보여요. 메뉴는 화면 맨 위를 누르세요.").
- **두 번 탭과의 충돌 방지**: 칸 위 한 번 탭은 250ms 동안 두 번째 탭을 기다렸다가 처리한다. 기다리는 동안 칸 테두리를 즉시 옅게 강조해(누름 반응) 느리다는 느낌을 줄인다. 가장자리 넘김(2번)은 기다리지 않는다.
- 2배 확대 상태에서는 칸 판정을 멈추고 일반 확대 상태 규칙(4.2)을 따른다. 맞춤으로 돌아오면 칸 판정 재개.
- 볼륨 키·스와이프 = 다음/이전 칸(칸 확대 상태 또는 자동 순서일 때), 쪽 전체 상태(눌러서 확대)에서는 다음/이전 쪽.

### 4.4 두 번 탭 대기와 즉시 반응

- 이북류는 두 번 탭 기능이 없으므로 모든 탭이 즉시 반응한다.
- 고정 쪽·만화: 가장자리 탭(넘김)은 즉시, 가운데(메뉴)만 250ms 대기 후 메뉴. 두 번 탭 확대는 가운데 영역에서만 인식한다(빠르게 연속 넘길 때 확대로 오인되지 않게).
- 대기 시간 250ms는 잠정값이다(M-12). 안드로이드 기본 두 번 탭 판정은 300ms라서, 줄이면 느린 두 번 탭이 한 번 탭 두 번으로 처리될 수 있다. 실험 ③ 결과로 확정한다.

| 상황 | 볼륨 아래 | 볼륨 위 |
|---|---|---|

## 5. 문구 가이드

### 5.1 원칙

1. **존댓말, 해요체**("열 수 없어요", "허용해 주세요"). 명령조·딱딱한 '~하십시오' 쓰지 않음.
2. **쉬운 말**: 사용자가 모르는 말은 바꾼다.

| 쓰지 않음 | 씀 |
|---|---|
| 파싱 오류, 렌더링 실패 | 내용을 읽지 못했어요 / 원본 모양으로 보여 드리지 못했어요 |
| 인코딩 | 글자 인코딩(괄호로 '글자가 깨질 때 바꿔요' 보충) |
| MIME, 시그니처 | 파일 종류 |
| 캐시 | 임시 저장 공간 |
| TTS | 듣기 / 읽어 주기 |
| 리플로우 | eBook 보기 |
| SAF | 폴더 고르기 |
| DRM | 서점 보호가 걸린 책 |

3. **원인 + 할 일** 순서로 쓴다. 사용자 탓으로 쓰지 않는다("잘못된 파일입니다" ✕ → "파일이 손상된 것 같아요" ○).
4. 버튼은 동사로 끝낸다: [열기] [허용하러 가기] [서재에 추가]. '확인'만 있는 버튼은 피한다.
5. 숫자·단위는 붙여 쓴다(3.2MB, 42쪽, 30분). 날짜는 2026-10-21 또는 '어제'·'3일 전'.
6. 오류 번호는 '자세한 정보' 안에만(E-형식-번호), 본문 문구에는 넣지 않는다.

## 6. 접근성(N-08) 확인 항목

## 대표님 결정 대기

2단계 목업 전에 정해 주시면 됩니다. 정해지지 않으면 각 항목의 '잠정안'으로 목업을 그리고 표시해 둡니다.

### 1. 본문 명조 글꼴 (M-09)

소설·eBook 보기의 기본 글꼴입니다. 크기는 앱(APK) 안에 압축해 넣었을 때의 실측값입니다(기술 설계서 3.5). 세 후보 모두 무료 공개 글꼴(OFL)이고 한글은 모두 들어 있으며, **한자는 모두 없어 기기의 한자 글꼴로 대신 표시**합니다.

| 안 | 글꼴 | 앱 크기 증가 | 굵은 글씨 | 느낌 |
|---|---|---|---|---|
| A | 리디바탕 | 약 0.7MB(가장 작음) | **없음** — 제목·강조의 굵은 글씨를 흉내 내어 그려 획이 조금 번짐 | 소설 읽기용으로 다듬어진 바탕체 |
| B | 나눔명조 (보통+굵게) | 약 1.9MB | 정상 | 가장 무난하고 익숙함 |
| C | 마루부리 (보통+굵게) | 약 4MB | 정상 | 부드럽고 현대적 |

**Noto Serif KR 포함 여부(별도 질문)**: 구글의 명조 글꼴로, 보통 굵기만 약 2.4MB(굵게 포함 시 더 커짐, 미측정)입니다. 위 A~C와 함께 **두 번째 명조로 더 넣을지**(앱이 그만큼 커짐) / **넣지 않을지** 정해 주세요. 넣으면 Aa 메뉴의 글꼴 칩이 하나 늘어납니다.

- 고딕은 어느 안이든 나눔고딕 보통 1종(약 1MB)을 함께 넣습니다(M-09).
- 잠정안: **B 나눔명조, Noto Serif KR 넣지 않음**(굵은 글씨가 정상이면서 크기가 적당함).

### 2. 앱 화면 색 (서재·설정 화면)

읽기 테마(주간·세피아·야간)와 형식 배지 색은 어느 안이든 같습니다.

| 안 | 내용 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| A | 'ASH 잉크' 고정 색(남색·종이색·갈색) | 앱 고유의 느낌, 아이콘·일러스트 색과 맞음 | 기기 다른 앱들과 색이 다를 수 있음 |
| B | 기기 배경화면 색 따르기를 기본 | 갤럭시 다른 앱들과 색이 맞음 | 배경화면에 따라 일러스트 색과 어울리지 않을 수 있음, Android 12 미만은 A로 표시 |

### 3. 칸 단위 보기에서 메뉴 여는 방법 (M-12와 함께 실험 ③ 후 확정)

칸 단위 보기에서는 칸을 누르면 확대되므로, 메뉴를 여는 자리를 따로 정해야 합니다.

| 안 | 방법 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| A | 화면 맨 위 띠(높이 12%)를 누르기 | 칸을 누를 자리가 가장 넓음 | 위 끝에서 아래로 밀면 상태 표시줄이 내려올 수 있음(실험 ③에서 확인) |
| B | 칸 바깥 가운데 여백 누르기 | 평소 방식과 같음 | 여백이 거의 없는 만화에서는 메뉴 열기가 어려움 |
| C | 화면 구석에 작은 메뉴 버튼을 늘 띄움 | 언제나 확실히 열림 | 그림 일부를 가림 |

- 잠정안: **A**(실험 ③에서 상태 표시줄 충돌이 확인되면 C로 바꾸는 안을 다시 여쭙겠습니다).
