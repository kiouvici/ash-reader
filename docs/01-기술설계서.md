## 1. 전체 구조

### 1.1 모듈 구성

```
ash-reader/
├─ build-logic/                # 컨벤션 플러그인(안드로이드 공통, NDK, Rust 빌드, 권한 검사 태스크)
├─ app/                        # Compose UI: 서재·설정·통계·서점 바로가기, 화면 이동, DI(Hilt)
├─ core/model/                 # DocId, Format, Locator, 공통 타입 (순수 Kotlin)
├─ core/data/                  # Room DB, DataStore(설정), Repository, 백업/복원(F-70)
├─ core/storage/               # 폴더 수집, SAF, 시그니처 판별(F-05), 문서 해시(F-63), 안전한 압축 해제(N-09)
├─ reader-core/                # 엔진 공통 인터페이스, 쪽 비트맵 캐시·미리 해석(F-58), 검색·선택 모델
├─ reader-ui/                  # 읽기 화면(탭 영역·정보줄·선택·형광펜 오버레이·두 쪽 배치)
├─ pagecurl/                   # 책 넘김 효과(GLES2 메시), 슬라이드, 효과 없음
├─ engine-mupdf/               # MuPDF 1.28.x 소스 빌드(ndk-build) + Java 바인딩(fitz), 합성 EPUB 리플로 엔진
├─ engine-djvu/                # DjVuLibre JNI (CMake)
├─ engine-archive/             # libarchive JNI(RAR4·RAR5), ZIP(java.util.zip) 파일명 인코딩 처리
├─ engine-comic/               # CBZ·CBR·고정 레이아웃 EPUB 쪽 목록·디코딩·타일·테두리 자르기·펼침 감지
├─ engine-hwp/                 # rhwp + JNI 크레이트(Rust, cargo-ndk) + hwplib/hwpxlib(대체 경로)
├─ engine-office/              # DOCX→XHTML(Kotlin), DOC(POI HWPF), RTF→XHTML(Kotlin)
├─ engine-convert/             # TXT 정리·목차, MOBI/AZW3(libmobi JNI), CHM(libmspack JNI) → 합성 EPUB
├─ feature-panels/             # 칸 인식(C++/OpenCV imgproc)
├─ feature-upscale/            # ncnn + 모델 파일, Vulkan/CPU 선택
└─ feature-tts/                # TextToSpeech + Media3 MediaSessionService
```

의존 방향: `app → reader-ui → reader-core ← engine-* / feature-*`. 엔진 모듈끼리는 서로 의존하지 않는다(합성 EPUB를 만드는 변환 모듈은 결과를 `reader-core`의 `ReflowSource`로만 넘김).

### 1.2 엔진 공통 인터페이스 (reader-core)

```kotlin
sealed interface OpenedDocument : Closeable {
    val docId: DocId; val format: Format; val outline: List<TocItem>
}
interface FixedDocument : OpenedDocument {           // PDF, DjVu, HWP 원본, 만화
    val pageCount: Int
    fun pageSize(index: Int): SizeF                    // pt 단위
    suspend fun render(index: Int, target: Bitmap, region: Rect, scale: Float, opts: RenderOpts)
    suspend fun text(index: Int): PageText?            // 글자+사각형(검색·선택·TTS), 없으면 null
}
interface ReflowDocument : OpenedDocument {            // 합성 EPUB 포함 모든 리플로 문서
    suspend fun layoutChapter(spec: LayoutSpec, chapter: Int): ChapterLayout  // 지금 장만 먼저(M-02)
    val pagination: StateFlow<Pagination>              // 전체 쪽 수 계산 상태(M-01)
    suspend fun render(page: PageRef, target: Bitmap, opts: RenderOpts)
    fun locatorOf(page: PageRef): Locator; fun pageOf(loc: Locator): PageRef
    suspend fun text(page: PageRef): PageText
    suspend fun renderRegion(page: PageRef, region: RectF, scale: Float, target: Bitmap) // 표 크게 보기(M-04)
    suspend fun tableAt(page: PageRef, point: PointF): TableRef?                     // 표 영역 판정
    suspend fun footnote(href: String): Footnote?       // 각주 팝업(F-46): 본문 조각 XHTML·텍스트
}
sealed interface Pagination {
    data class Counting(val chaptersDone: Int, val chaptersTotal: Int) : Pagination // 진행률·장 안 쪽만 표시
    data class Ready(val totalPages: Int, val chapterStarts: IntArray) : Pagination  // 쪽 수 표시로 전환
}
data class RenderOpts(val theme: ThemeSpec, val overlays: List<Overlay>, val forCurl: Boolean)
// Overlay = 형광펜·검색 결과·TTS 읽는 문장 사각형(색 포함). forCurl=true면 overlay를 비트맵에 직접 합성(M-03)
```

`FixedDocument`도 같은 `RenderOpts`를 받는다. HWP·PDF 원본의 `renderRegion`은 기존 `render(region=…)`로 대신한다.

`Locator`는 형식 무관 위치 표현: `{chapter, mupdfMark?, charOffset?, textQuote?, page?, progression}`. 글자 크기를 바꿔 쪽이 다시 나뉘어도 MuPDF `makeBookmark/findBookmark`로 같은 위치를 찾는다.

### 1.3 Kotlin/Compose·빌드 환경

| 항목 | 값 |
|---|---|
| 언어 | Kotlin 2.x, 코루틴/Flow |
| UI | Jetpack Compose(Material 3). 읽기 표면은 `AndroidView(TextureView)`(GL 넘김) |
| DI | Hilt |
| minSdk / targetSdk / compileSdk | 26 / 36 / 37 (빌드 골격 `build/skeleton` 기준: AGP 9.4.0, Kotlin 2.4.21, Compose BOM 2026.09.00). edge-to-edge 강제 → 읽기 화면은 전체 화면이라 문제 없음 |
| NDK | r28 이상(16KB 페이지 정렬 기본값). MuPDF fitz 1.28.5의 `build.gradle`이 NDK 28.2.13676358 사용 |
| AGP | 9.4.0(골격). 8.5.1 이상이면 비압축 .so 16KB zip 정렬 |
| Rust | rhwp가 고정한 1.93.1(`rust-toolchain.toml`), cargo-ndk 4.1.2 |
| ABI | 배포 = `arm64-v8a` 단일 APK(M-10). `armeabi-v7a`는 최저 기기 시험용 별도 산출물(대표님께 전달 안 함), 디버그에만 `x86_64`(에뮬레이터) |

16KB 페이지: Play 배포가 아니어도 16KB 페이지 기기(Android 15+ 일부)에서 정렬 안 된 `.so`는 로드 실패하므로, CI에서 `zipalign -c -P 16 -v 4` 와 `llvm-objdump -p *.so | grep LOAD`(align 2**14) 검사를 넣는다.

### 1.5 APK 크기 예상 (arm64-v8a 단일 APK, 대부분 추정)

| 구성 | 예상 | 근거 |
|---|---|---|

| OpenCV 최소 빌드 | 2~4MB | (미확인) |
| ncnn(Vulkan 포함) + Real-CUGAN 2x 모델 | 4~6MB | 모델 `up2x-conservative.bin` 2,573,648B(저장소 실측) |

| Kotlin/Compose/AndroidX | 4~6MB | |
| **합계** | **약 40~60MB (arm64 단일 APK)** | 유니버설 APK는 만들지 않음 |

배포(M-10): 릴리스 산출물은 `ndk.abiFilters += "arm64-v8a"`로 만든 **arm64 APK 하나**(`ash-reader-<versionCode>-<sha>-release.apk`)만 대표님께 전달한다. armeabi-v7a는 CI의 별도 변형(`minDeviceRelease`, `abiFilters += "armeabi-v7a"`)으로 만들어 시험 산출물에만 올린다. 64비트를 지원하지 않는 기기(32비트 전용)에서 설치가 거부되는 점은 '알려진 제약'으로 둔다. 요구사항 1단계 ⑤의 "AI 모델로 인한 APK 증가 상한 50MB"는 충분히 지킨다(6MB 이하).

## 2. 형식별 엔진 선정표

라이선스 원문은 11장 출처에 링크. "최근 커밋"은 2026-10-21 기준 기본 브랜치 HEAD.

| 형식 | 1순위 엔진 | 대안 | 라이선스(원문 확인) | 안드로이드 통합 | 유지보수(확인값) | 위험 |
|---|---|---|---|---|---|---|
| PDF | MuPDF 1.28.5 | 안드로이드 `PdfRenderer`(텍스트 추출 불가) | AGPL-3.0-or-later (`COPYING`, 소스 헤더) | `mupdf-android-fitz` AAR를 소스에서 빌드(JNI, Java 바인딩) | fitz 1.28.5 태그, 2026-09-25 커밋 / mupdf master 1.29.0 개발 중 2026-10-21 커밋 | 낮음 |
| XPS | MuPDF | – | 위와 같음 | 위와 같음 | – | 요구사항 3장에 없음(P15). 인텐트 필터·서재 수집에 등록하지 않는다. 시그니처로 XPS가 판별되면 '지원 안 하는 형식' 안내(S-43, 알아낸 형식: XPS)로 처리하고 MuPDF로 열지 않는다(범위 밖 기능을 몰래 제공하지 않음) |
| EPUB 2·3 | MuPDF EPUB 처리기 + 사용자 CSS + 줄바꿈 패치 | Readium kotlin-toolkit(BSD-3, WebView 기반) | AGPL-3.0 | 위와 같음 | – | MuPDF CSS는 부분 지원(float·position 제약) → '원본 CSS 끄기' 설정(3.2). **고정 레이아웃(pre-paginated)** 은 MuPDF 리플로로 열지 않고 만화 엔진으로(2.2). **DRM**은 판별 후 안내(2.2) |

### 2.2 EPUB 특수 경우 (M-07)

- **고정 레이아웃(pre-paginated)**: OPF `<meta property="rendition:layout">pre-paginated</meta>`(문서 전체) 또는 spine `properties="rendition:layout-pre-paginated"`가 과반이면 고정 레이아웃으로 본다.
  - 각 spine 항목이 이미지 1장만 감싼 XHTML이면(만화·화보형, 가장 흔함) 그 이미지 경로 목록으로 `engine-comic`의 `ComicSource`를 만든다 → 만화 기능(넘김 방향·두 쪽·칸·AI 화질)을 그대로 쓴다. `page-progression-direction=rtl`은 F-49 자동 방향.
  - 글자가 섞인 고정 레이아웃(그림책·잡지형)은 MuPDF로 각 XHTML을 viewport(`<meta name="viewport" content="width=…,height=…">`) 크기로 `layout()`해 한 쪽씩 비트맵으로 만든 뒤 같은 `ComicSource`에 넣는다(텍스트 선택은 ○).
- **DRM 판별**: `META-INF/encryption.xml`에 `EncryptedData`가 있고 그 `EncryptionMethod`가 글꼴 난독화(`http://www.idpf.org/2008/embedding`, `http://ns.adobe.com/pdf/enc#RC`)뿐이면 DRM 아님(글꼴만 난독화 해제해 연다. MuPDF는 encryption.xml을 읽어 암호 항목을 표시하고 "EPUB may be locked by DRM" 경고만 냄 — 코드 확인). 그 밖의 알고리즘이 본문(xhtml)에 걸려 있거나 `META-INF/rights.xml`(Adobe ADEPT)·`META-INF/license.lcpl`(Readium LCP)·리디 등 서점 전용 표식이 있으면 → '서점 보호가 걸린 책' 안내(S-43, D-002). 해제는 시도하지 않는다.
- AZW3·MOBI: EXTH 401/402·암호 플래그(PalmDOC 헤더 encryption≠0)면 같은 안내.

## 3. 렌더링 구조

### 3.1 공통 흐름

```
[원본] ─ 시그니처 판별 ─┬─ 고정 쪽(PDF·DjVu·HWP 원본·만화) ─ FixedDocument.render ─┐
                       └─ 리플로(EPUB·FB2·HTML·TXT·RTF·MOBI·AZW3·CHM·          │
                          DOCX·DOC·HWP 이북식) → 정규화 XHTML → 합성 EPUB         │

                                                                               ▼
                         쪽 비트맵 캐시(F-58, RAM 1/8 상한, LRU) → 넘김 효과(pagecurl) / 스크롤 보기
```

- 쪽 비트맵은 화면 해상도 ARGB_8888.
- **테마 적용 위치(M-05)**: 리플로 문서는 테마(바탕·글자·링크색, 사용자 테마)를 **사용자 CSS**로 넣어 MuPDF가 그 색으로 렌더한다(테마를 바꾸면 그 장 쪽 비트맵을 다시 렌더, 다시 조판은 안 함 — 색만 바뀌므로 `layout()` 불필요). 고정 쪽 문서(PDF·DjVu·HWP 원본·DOCX 구조 보존·만화)는 원본 비트맵 위에 **셰이더/ColorMatrix 후처리**: 야간 = 반전(그림 영역 제외 마스크 3.6), 세피아 = 종이색 곱하기, 사용자 테마 = 휘도→2색 사상. 색온도(F-42)·추가 어둡게는 모든 형식 공통으로 맨 위 덧씌움 층(비트맵에 굽지 않음).
- **강조 합성(M-03)**: 평소에는 형광펜·검색 결과·TTS 문장 강조를 `reader-ui` 오버레이로 그린다. 넘김이 시작되는 순간(`forCurl=true`) 현재·다음 쪽 비트맵에 그 강조를 곱하기(multiply) 모드로 구워 텍스처로 올린다 → 말려 넘어가는 종이에도 강조가 따라간다. 정보줄(F-45)은 쪽 비트맵에 넣지 않고 화면에 고정된 별도 층.
- 확대 시에는 같은 엔진으로 보이는 영역만 타일 렌더(256~512px 타일).

6. 들여쓰기(F-40): 사용자 CSS `p{text-indent:Nem}`, 대화문은 정규화 단계에서 `"「『“`로 시작하는 문단에 `class="dlg"` 부여.

#### 쪽 수 계산과 다시 조판 (M-01, M-02)

- 문서를 열면 **지금 장만** `layout()`해 바로 보여 준다. 나머지 장은 백그라운드 코루틴(우선순위 낮음, 한 장씩, 취소 가능)으로 쪽 수를 센다. 상태는 `Pagination.Counting(장 n/전체 m)` → `Ready(총 쪽 수)`.
  - `Counting` 동안 UI(S-21 슬라이더·정보줄)는 **전체 진행률(%) + 이번 장 안 쪽(예: '3장 5/18쪽')** 만 표시하고, `Ready`가 되면 '42 / 210쪽'으로 바꾼다. 슬라이더는 Counting 동안 진행률(문자 오프셋 비율) 기준으로 이동.
  - 결과(장별 쪽 수)는 `layout_cache`(docId, layoutKey = 화면 크기·글꼴·크기·간격·여백·줄바꿈 설정 해시, chapterPages)로 저장 → 같은 설정으로 다시 열면 즉시 `Ready`.
- **설정 변경(M-02)**: 글자 크기·간격·여백·글꼴 슬라이더는 손을 뗀 뒤 **0.3초 디바운스** 후 **지금 장만** 다시 조판해 현재 Locator 위치로 이동하고, 다른 장은 무효화 후 백그라운드 재계산(`Counting`으로 돌아감). 끄는 동안에는 현재 쪽 비트맵을 비율로 늘린 미리보기만 보여 준다. 두 손가락 글자 크기 조절은 기본 끔(설정에서 켜면 같은 디바운스 경로).
- 다시 조판 중 이전 결과는 즉시 버리지 않고(화면 깨짐 방지) 새 장 조판이 끝나면 교체한다.

#### 스크롤 보기 조판 (M-05, F-22)

- 리플로 문서의 스크롤 보기는 **쪽 높이를 매우 크게(장 하나가 한 '쪽')** 잡아 `layout(w, 32767pt, em)`로 장마다 한 번 조판하고, 위아래 여백 없이 장을 이어 붙인다. 화면에는 보이는 띠(화면 높이×3)만 타일 단위(높이 1024px)로 렌더 → RecyclerView/LazyColumn 대신 자체 타일 스크롤러.
  - MuPDF 쪽 높이 상한에 걸리는 긴 장은 여러 '쪽'으로 나눠지지만 여백 없이 이어 붙이므로 사용자에게는 끊김이 없다(경계에서 줄이 잘리지 않게 쪽 경계는 MuPDF가 줄 단위로 정한다).
  - 위치는 같은 Locator(북마크)로 쪽 보기↔스크롤 보기 전환 시 유지. 스크롤 보기에서는 넘김 효과 없음(F-17).

#### 원본 CSS 끄기와 표·각주 (M-04, F-46, R-04)

- **원본 CSS 끄기**: 보기 설정(S-24) '문단' 탭 아래 '책의 글꼴·간격 무시하기'(가칭) 스위치 → `Context.useDocumentCSS(false)` + 앱 기본 CSS만 적용. 문서별 기억. 기본은 원본 CSS 사용 + 앱 CSS가 글꼴 크기·줄 간격·여백·색을 `!important`로 덮어씀.
- **넓은 표(M-04)**: 이북식 보기의 표는 사용자 CSS `table{max-width:100%; table-layout:auto}` + 셀 글자 축소 하한(본문의 70%)으로 폭에 맞춘다. 그래도 넘치거나 셀이 너무 작으면 표 오른쪽 위에 '표 크게 보기' 표지를 둔다 → 누르면 `tableAt()`로 표를 찾고, **원래 열 너비로 별도 조판한 표 하나**(표 XHTML 조각을 넓은 가상 쪽 폭으로 `layout()`)를 `renderRegion()`으로 타일 렌더해 확대·이동 가능한 창(S-32 확대 규칙)으로 보여 준다. HWP·DOCX 이북식은 원본 표 구조를 그대로 넣으므로 같은 경로.
- **각주(F-46)**: EPUB `epub:type="noteref"` 링크(또는 `href="#id"`가 같은/다른 파일의 `aside epub:type="footnote"`·`endnote`·`rearnote`를 가리키는 링크)를 정규화 단계에서 표시해 둔다. 누르면 `footnote(href)`가 대상 요소의 XHTML 조각을 꺼내 팝업 카드(S-29)에 별도 소형 조판으로 렌더 → 읽던 쪽은 그대로. 본문 흐름 안의 각주 본문(`aside`)은 사용자 CSS로 숨김(`aside[epub|type~=footnote]{display:none}`). 대상이 일반 문단이면(EPUB2) 그 문단 하나를 꺼내 보여 준다. FB2 `<notes>`·DOCX `footnotes.xml`·HWP 각주도 같은 `Footnote` 구조로 낸다.

#### 합성 EPUB

- 변환기들이 `ReflowSource(chapters: List<Xhtml>, toc, resources, lang, direction)`를 만들면, `engine-mupdf`가 OPF·nav를 생성해 MuPDF `TreeArchive`(메모리)로 연다. `openDocument(name, Archive)` 경로가 EPUB 처리기와 맞물리는지는 **(미확인)** → 안 되면 앱 캐시에 무압축(STORED) EPUB 임시 파일을 쓰고 닫을 때 지운다.
- 대용량(TXT 10MB 등): 장(또는 약 200KB) 단위로 나눠 장별 지연 조판. 전체 쪽 수는 백그라운드 계산 후 MuPDF accelerator를 앱 캐시에 저장(키 = docId + 화면크기 + 글꼴설정 해시).
- 글꼴: Android용 MuPDF는 `-DTOFU_CJK`로 CJK 내장 글꼴이 빠져 있음(`Android.mk` 확인) → `Font.installFontLoader`로 한국어 글꼴 공급. 세부는 3.5.

#### 텍스트 선택·형광펜·검색·TTS(리플로)

- MuPDF `StructuredText`로 쪽별 글자 사각형(quad) 확보 → 선택 손잡이·형광펜 오버레이를 `reader-ui`에서 그린다.
- 형광펜·메모 위치는 `{chapter, textQuote(선택 문자열), prefix 32자, suffix 32자, approxCharOffset}`로 저장(W3C TextQuoteSelector 방식). 글자 크기·화면 크기가 바뀌어도 장 안에서 다시 찾아 고정. 원본 파일엔 쓰지 않음(F-11).
- 검색: 장 단위 정규화 텍스트(U+2060 제거, 공백 정규화)에서 찾고 quad로 표시.

### 3.3 HWP/HWPX 원본 보기 렌더 출력

rhwp 공개 API(`wasm_api.rs`, 네이티브에서도 rlib로 사용 가능): `HwpDocument::from_bytes / from_bytes_with_password`, `page_count`, `render_page_svg`, `get_page_layer_tree`(PaintOp JSON: TextRun, GlyphRun, Line, Rectangle, Ellipse, Path, Image, Equation 등), `get_page_text_layout`, `get_page_info`. 저장소의 `bindings/Native`(C ABI)는 텍스트 함수 4개뿐이라 렌더용은 직접 만든다.

| 방식 | 내용 | 장점 | 단점 | 채택 |
|---|---|---|---|---|
| A. SVG → resvg(Rust 안) → RGBA → `AndroidBitmap_lockPixels` | `render_page_svg` 결과를 같은 `.so` 안에서 resvg(tiny-skia)로 래스터 | Rust 안에서 끝남, armv7도 됨, 데스크톱 SVG 결과와 같음 | 한 쪽 SVG가 크다(실측 real-01 14쪽 4.6MB, 쪽당 `<text>` 약 300개), 글꼴은 fontdb에 직접 등록 | **1순위** |
| B. PageLayerTree → Kotlin `Canvas` 재생 | PaintOp를 안드로이드 Canvas 호출로 1:1 재생 | 확대 시 벡터 품질, 텍스트 선택에 유리 | PaintOp 20종+ 직접 구현, 스키마 변동 위험 | 대안(실험 ①에서 A가 느리면) |
| C. rhwp `native-skia`(skia-safe) PNG | 공식 PNG 경로 | 결과 검증됨 | skia-safe는 aarch64/x86_64만(armv7 불가), `.so` 수십 MB | 제외 |

- JNI 크레이트 `ash-hwp-jni`(cdylib, `jni` 크레이트 사용): `open(bytes, password?) → handle`, `pageCount`, `pageSizePt(i)`, `renderPage(handle, i, scale, bitmap, tileRect)`, `extractXhtml(handle)`(이북식), `close`. uniffi(Kotlin 바인딩 자동 생성)는 JNA 의존(라이브러리 약 1MB+, 비트맵 직접 쓰기 불편)이라 쓰지 않는다.
- 글꼴 대응(F-29): SVG `font-family` 목록에 rhwp가 이미 대체 목록을 넣는다(실측: `'함초롬바탕','Batang',…,'Nanum Myeongjo',…,'Noto Serif KR',…,serif`). fontdb에 번들 명조·고딕(3.5, MuPDF와 같은 TTF 파일 공유) + 시스템 CJK 글꼴을 등록하면 대체 글꼴로 자동 연결. 줄 배치는 rhwp 내장 글꼴 메트릭(`font_metrics_data.rs`)로 계산돼 화면 글꼴이 달라도 쪽 나눔은 유지된다.
- 자동 전환(F-28, 요구사항 v0.6.2 문구): 렌더는 별도 스레드. 다음 중 하나면 이북식으로 자동 전환하고 S-44 안내.
  1. 파싱 오류 또는 패닉(`catch_unwind`로 잡아 오류 코드로 반환, 앱 종료 없음)
  2. 첫 쪽 렌더가 10초 초과(N-10의 시작 시각 기준)
  3. **첫 쪽이 비어 있으면서 문서 본문 텍스트는 있는 경우(P13)**: '비어 있음' = 렌더 비트맵에서 바탕색과 다른 픽셀이 0.1% 미만(가장자리 2% 여백 제외, 64×64 축소본으로 판정). '본문 텍스트 있음' = `extractXhtml`(또는 `get_page_text_layout` 전체)의 공백 제외 글자 수 ≥ 1. 진짜 빈 쪽으로 시작하는 문서(표지 앞 빈 쪽)는 텍스트 기준을 첫 쪽 텍스트가 아닌 **문서 전체**로 보므로 오판 가능 → 첫 쪽의 `get_page_text_layout` 글자 수도 0이면 '원래 빈 쪽'으로 보고 전환하지 않는다(첫 쪽에 글자가 있는데 그림이 비어 있을 때만 전환).
- **앞 3쪽 미리 해석(M-06)**: 문서를 열면 1쪽을 그리고 곧바로 2·3쪽을 백그라운드에서 렌더해 둔다(이후 F-58 규칙: 넘김 방향 2쪽·반대 1쪽). 아직 렌더되지 않은 쪽으로 이동하면 **쪽 크기(get_page_info)만큼 현재 테마 바탕색의 빈 종이**를 먼저 그리고 가운데 작은 원형 진행 표시, 렌더가 끝나면 교체. 넘김 효과도 이 빈 종이 비트맵으로 진행된다(멈추지 않음).
- 사전 실측(x86_64 서버, 참고용): real-01.hwpx(829KB) 14쪽 SVG 전체 0.15초, real-02.hwp(951KB) 9쪽 0.11초, skia PNG 14쪽 2.5초. 1쪽 표·직인 이미지 정상(육안). MuPDF의 HWPX 텍스트 처리기는 같은 파일을 26쪽 리플로 텍스트로만 연다(대체 경로로 사용 가능).
- 쪽 수 ±1(F-26 합격 기준): 한컴 PDF 출력본과 비교 필요(대표님께 PDF 출력본 요청).

### 3.4 DOCX 구조 보존 보기

- 사전 실측: MuPDF `office.c`(DOCX·HWPX 처리기)는 `w:p/w:r/w:t` 텍스트만 HTML로 옮기고 표·그림·머리글/바닥글은 버린다(real-04.docx 2쪽 텍스트만 출력). → F-30 불충족이라 자체 변환기를 둔다.
- 자체 변환기(Kotlin, `XmlPullParser`): `document.xml`, `styles.xml`(상속), `numbering.xml`(번호·글머리), `_rels`, `media/*`, `header*/footer*.xml`(default/first/even), `footnotes.xml`. 표는 `w:gridSpan`→colspan, `w:vMerge`→rowspan, `w:tcBorders`/`w:tblBorders`→CSS border. 그림은 `w:drawing//a:blip/@r:embed`, VML `v:imagedata`. EMF/WMF는 2.3.
- 조판(2026-10-23 배치 4D 구현, D-017): **Word 쪽 크기·여백 그대로의 PDF**를 만들어 기존 PDF 경로(쪽 맞춤·확대, 글자 선택·검색·형광펜)로 연다.
  1. `:engine-office` `DocxPaged`(DOCX)·`RtfPaged`(RTF, '.doc' 이름 RTF 포함)·`DocPaged`(DOC, POI HWPF) → `PagedWord`(구역별 쪽 크기·여백·머리글/바닥글 거리, 머리글/바닥글 first/even/default, 쪽 번호 시작·형식, 본문·머리글·각주 XHTML 조각, 떠 있는 그림). 공통 출력기 `WordHtml`이 문단(정렬·들여쓰기·내어쓰기·앞/뒤 간격(겹침=큰 쪽)·줄 간격(배수/고정/최소, 글꼴별 Word 한 줄 배수)·탭)과 표(격자 너비·테두리·음영·병합·행 높이·칸 여백)를 낸다.
  2. `:engine-mupdf` `PagedComposer`: 구역 본문을 '본문 폭 × 200,000pt' 갤리 한 장으로 MuPDF가 조판(명시적 쪽 나눔은 `page-break-after` div로 갤리 쪽을 나눔) → StructuredText의 줄·그림·선 위치에서 **어떤 줄·표 칸(세로 테두리)도 가르지 않는 자리**로 쪽을 자름. 쪽마다 머리글(높이만큼 본문을 내림)·본문 조각(clip + 글리프 기준선 필터 장치로 쪽 밖 글자는 PDF에 넣지 않음)·각주(그 쪽 참조분, 본문 높이에서 뺌)·바닥글·글 뒤/앞 그림을 `DocumentWriter`로 그림. 쪽 번호 필드는 `{{ASH_PAGE}}`·`{{ASH_PAGES}}` 자리표시를 쪽마다 바꿈. 문단 앞 간격·조각 끝은 보이지 않는 링크 표지(`#ash-sb-pt`, `#ash-end`)로 합성기에 알림.
  3. MuPDF HTML 제약 대응: 탭·inline-block 미지원 → 탭 문단은 테두리 없는 한 줄 표(탭 위치마다 칸, 오른쪽/가운데 정렬·점 채움 칸), float·position 미지원 → 글 뒤/앞(wrapNone·behindDoc) 그림은 합성기가 쪽 좌표로 직접 그리고, 둘러싸기(square/tight/through/topAndBottom)는 문단 앞 블록 그림(가로 위치 유지)으로 근사, `page-break-before` 무시 → div 쪽 나눔.
  4. 글꼴: 한글·한자 묶음은 동아시아 글꼴(고딕류 → 나눔고딕, 그 밖 → 나눔명조), 라틴 묶음은 라틴 글꼴(한국어 글꼴이면 같은 번들, 아니면 MuPDF 내장 Times/Helvetica 계열), 나눔에 없는 기호(「」※○①→ 등)는 리디바탕. Word 한글 글꼴 폭(1em)에 맞추려 한글 묶음만 1.05배, 한양(HY)·'체' 글꼴은 낱말 사이 공백 0.5em(실측).
  5. 결과는 `cache/office/<docId>/original-v1.pdf`(변환 캐시 규칙). 암호 DOCX는 닫을 때 지우는 임시 폴더. 실패하면 '이북식 보기로' 안내.
  - 한계: 다단(cols) 무시(한 단), 위젯/과부 제어 없음, 글상자는 문단 뒤 블록, 표 스타일 조건부 서식(첫 행 등) 미적용, '최소/고정' 줄 간격에서 Word는 여분을 글자 위에 두지만 여기서는 위·아래 반씩, DOC 각주 본문·사용자 탭 위치 미지원, 목차(outline) 없음(원본 보기).
- **암호 DOCX(M-08)**: Word 2007+ 암호 파일은 ZIP이 아니라 OLE 컨테이너(`EncryptionInfo` + `EncryptedPackage`)다. 실험 ②에서 두 방식을 검증한다.
  1. 1순위: POI `poi`(OLE 읽기) + `org.apache.poi.poifs.crypt.Decryptor`(Agile·Standard AES, SHA-512 키 유도)로 메모리 안에서 풀어 ZIP 바이트를 얻은 뒤 기존 변환기로. POI 암호 해제가 안드로이드에서 `javax.crypto`만으로 동작하는지, `poi-ooxml` 없이 되는지 확인(미확인).
  2. 대안: 자체 Kotlin 구현(Agile Encryption: `EncryptionInfo` XML 파싱 → PBKDF 유사 SHA-512 반복 → AES-CBC 세그먼트 4096B 복호화), 약 300줄.
  3. 둘 다 안 되면 M-08대로 '이 암호 방식은 열 수 없어요' 안내. RC4(Office 97-2003 DOC 암호)는 지원하지 않고 안내.
  - 입력한 암호는 메모리에서만 쓰고 저장하지 않는다(F-34). 풀린 ZIP 바이트도 디스크에 쓰지 않는다.
- EMF/WMF 그림: 회색 상자 + 안내 문구(2.3). 
- POI XWPF 대안: poi-on-android 예제가 minSdk 26 + POI 5.5.1로 동작을 보이지만 xmlbeans/ooxml-lite로 APK가 크게 늘고(미확인, 약 10MB+) StAX 시스템 속성 설정이 필요. 자체 변환기 공수가 예상의 1.5배를 넘으면 전환.

### 3.6 화면 설계서(02) 연동 사항

- **원본/이북식 전환 위치 잇기(S-32)**: HWP는 `get_page_text_layout`으로 쪽의 첫 문단 (구역, 문단 번호)를 얻어, 이북식 XHTML에 같은 번호를 `id="s{n}p{m}"`로 심어 둔다 → 원본→이북식은 그 id의 MuPDF 위치로, 이북식→원본은 현재 쪽 첫 문단 id로 rhwp 쪽을 찾는다. DOCX도 변환 시 문단 순번 id를 공유한다. 글자 있는 PDF의 이북식(○)은 MuPDF 문단(StructuredText 블록) 순번으로 근사.
- **형식별 도구줄(화면 설계서 3.6 표)**: 문서를 열기 전에 도구줄이 정해져야 하므로 `Format`과 함께 `Capabilities`(hasText, canReflowView, hasToc, isComic)를 시그니처 판별 직후 계산한다. "PDF(글자 있음/스캔)" 구분은 첫 3쪽 StructuredText 글자 수 합계로 판정(공백 제외 50자 이상 = 글자 있음). **판정 전에는 도구줄 4번 칸을 비워 둔다(M-13)** — `Capabilities.reflowView`가 `Unknown → Available/Unavailable`로 바뀌는 StateFlow. PDF 원본↔이북식 전환 위치는 "대략 같은 위치"(블록 순번 근사)로 기대치를 명시(M-13).
- **두 쪽 펼침**: 리플로 문서는 펼침 한 면 폭(화면 폭/2 − 가운데 여백)으로 `layout()`을 다시 하므로 세로↔가로 회전 때 쪽 수가 바뀐다 → 위치는 Locator(북마크)로 유지. 고정 쪽 문서는 쪽 2장을 각각 렌더해 한 텍스처로 합친다. 펼침 짝 맞추기(F-50 첫 쪽 단독·한 쪽 밀기)는 `reader-core`의 `SpreadPlanner`가 쪽 번호→펼침 번호 표를 만든다.
- **탭 대기·위 띠 메뉴(M-12)**: 안드로이드 기본 두 번 탭 판정은 `ViewConfiguration.getDoubleTapTimeout()`(300ms). 대기 시간은 상수가 아닌 설정값(`TapConfig.doubleTapWaitMs`, 기본 250)으로 두고, 실험 ③에서 200/250/300ms와 위 띠 위치(위 0~12% / 6~18%)를 비교해 확정한다.
- **넘김 손가락 50% 기준(4.2)**: `pagecurl`에서 놓은 순간 말림 진행도와 손가락 속도(빠른 튕김이면 진행도와 무관하게 넘김)를 함께 쓴다.
- **고정 쪽 세피아 '종이색 곱하기'·야간 반전 '그림 제외'**: 반전은 셰이더 한 번이지만 '그림 제외'는 그림 영역을 알아야 한다 → PDF는 MuPDF가 이미지 그리기 위치를 알려 주므로(Device 콜백) 그 사각형만 반전 제외, DjVu·스캔 PDF·만화는 쪽 전체가 그림이라 '그림 제외'가 의미 없음(스위치 숨김). HWP 원본은 rhwp PaintOp `Image` 위치 사용.
- **고정 쪽 검색 진행 표시(S-23)**: MuPDF 검색은 쪽 단위 동기 호출이라 백그라운드 코루틴으로 쪽마다 돌리고 `Cookie`로 중단한다.
- **AI 화질 '그래픽 메모리가 부족해요' 문구(S-33)**: 숨김 이유는 RAM 부족·Vulkan 미지원+CPU 너무 느림·발열 3가지라 문구를 원인별로 나눈다.

### 4.2 설계

- `:pagecurl`은 입력으로 "현재/다음/이전 쪽 비트맵(또는 펼침 비트맵)"만 받는다 → 형식 무관(F-17).
- 렌더 표면: `TextureView` + 전용 GL 스레드(EGL14), Compose에는 `AndroidView`로 삽입. GLSurfaceView는 Compose 안 z-순서 문제로 쓰지 않는다.
- 메시: 쪽을 40×60 격자, 손가락 위치로 말림 축(직선)·반지름 계산, 축 너머 정점을 원통에 감음. 뒷면은 같은 텍스처를 좌우 반전 + **현재 테마 바탕색**(주간 흰색, 세피아 `#F4ECD8`, 야간 `#121212`, 사용자 테마 바탕색 — uniform `u_backColor`) 70% 섞기(종이 비침, M-03), 그림자는 프래그먼트 셰이더의 거리 기반 그라디언트.
- 두 쪽 펼침(F-18): 왼쪽/오른쪽 쪽 텍스처 2장 + 아래에 깔린 다음 펼침 2장. 왼→오 방향은 오른쪽 쪽만 말려 왼쪽으로 넘어가고 뒷면에 다음 펼침의 왼쪽 쪽이 보임.
- 오→왼(F-48): 정점 x좌표 반전 행렬 하나로 처리(텍스처 좌표는 그대로). 두 쪽 배치 순서도 반전. 위→아래는 넘김 효과 없음(웹툰 스크롤).
- 텍스처: 쪽 비트맵을 `GLUtils.texImage2D`로 업로드, 2의 거듭제곱 제약 없음(ES 2.0 NPOT + CLAMP). 최대 텍스처 크기(`GL_MAX_TEXTURE_SIZE`) 초과 시 축소본 사용.
- 넘김 중에는 미리 해석된 비트맵만 쓴다(F-58). 다음 쪽이 준비 안 됐으면 저해상도 미리보기(없으면 3.3의 바탕색 빈 종이)로 시작하고 끝난 뒤 교체.
- 강조 합성: 넘김 시작 시 현재·다음 쪽 텍스처는 강조가 구워진 비트맵(3.1, `forCurl=true`). 넘김이 끝나면 강조 없는 비트맵 + 오버레이로 되돌린다. 정보줄은 GL 표면 밖 고정 층.
- 넘김 중 일시정지 신호: `pagecurl`은 `isAnimating: StateFlow<Boolean>`을 내보내고, AI 화질 향상·칸 인식·쪽 수 계산 큐는 이 값이 true인 동안 새 작업을 꺼내지 않는다(6.2).
- 슬라이드/효과 없음(F-16): Compose `HorizontalPager` 대신 같은 표면에서 평면 이동(코드 공유).
- 측정(N-06, v0.6.2): **판정값 = GL 렌더 스레드의 vsync 대비 프레임 완료 지연 비율**(JankStats는 참고값). 측정 규칙은 9.0. 최저 기기에서 느리면 기본값 '효과 없음'(N-06 허용).

### 6.2 실행 설계

- 실행: ncnn `Net` + `opt.use_vulkan_compute = (기기 Vulkan 1.0+ 지원 && GPU 화이트리스트 통과)`. 실패 시 CPU(arm NEON, fp16 저장, 스레드 = 빅코어 수).
- 타일: 입력 200×200 타일 + 겹침 16px로 나눠 처리(메모리 상한), 결과 이어 붙이기.
- 조건(F-73): 쪽 짧은 변 < 화면 짧은 변(px)인 쪽만. 앞쪽부터 백그라운드 큐(`WorkManager` 아님, 문서 열린 동안만 도는 코루틴), 결과는 앱 캐시 `upscale/<docId>/<page>.webp`(무손실), 상한 1GB LRU.
- 발열·배터리: `PowerManager.getThermalHeadroom`(API 30+) / `ACTION_BATTERY_CHANGED` 온도, 배터리 15% 이하·절전 모드면 멈춤. Android 8~10은 배터리 온도만 사용.
- **판정 시점**: 앱 첫 실행 때가 아니라 **사용자가 만화 설정(S-33) '화질' 탭을 처음 열 때** 1회 판정한다(앱 시작을 늦추지 않음). 순서: ① RAM(`ActivityManager.MemoryInfo.totalMem`) 3GB 미만 → 숨김(이유: 메모리) ② Vulkan 1.0+ 지원·화이트리스트 확인 ③ 256×256 입력 1회 시험 추론(약 0.2~2초, 진행 표시) → 쪽당 예상 시간 = 시험 시간 × (800×1200)/(256×256). GPU 예상 > 15초이고 CPU도 > 15초면 숨김(이유: 속도). 결과·앱 버전·GPU 드라이버 버전을 DataStore에 저장하고, 앱 업데이트·드라이버 변경 시 다시 판정. 최저 기기는 숨김 안내로 합격(F-73).
- 숨김 이유 문구는 3가지(메모리 / 그래픽 처리 미지원·너무 느림 / 기기 온도로 일시 사용 불가)로 나눠 UX에 전달.
- **넘김 중 일시정지**: 넘김 애니메이션(`pagecurl.isAnimating`)·확대 제스처 중에는 진행 중인 타일을 마치고 다음 타일을 꺼내지 않는다(GPU를 넘김 렌더에 양보, N-06 보호). 애니메이션이 끝나고 300ms 뒤 재개. 처리된 쪽 바꿔 끼우기(0.2초 페이드)는 넘김 중에는 미뤘다가 끝난 뒤 한다.
- 속도 추정(미확인, 실험 ⑤에서 측정): 기준 휴대폰 갤럭시 S26 울트라(스냅드래곤 8 Elite Gen 5 — 보도 기준)에서 800×1200 입력 2x Real-CUGAN GPU 1~3초, CPU 8~20초. 기준 태블릿(9.0.2)은 GPU 계열이 확인되기 전까지 CPU 경로를 기본으로 측정한다. 5초 기준을 못 맞추면 Real-CUGAN `models-nose`(잡음 제거 없는 가벼운 판) → waifu2x cunet 순으로 바꾸거나, 타일 크기·처리 해상도를 낮춘다. 그래도 안 되면 요구사항 8장대로 ○ 또는 다음 버전.

## 7. TTS·저장소·DB·문서 식별·백업

### 7.1 TTS (F-13, F-47)

- `TextToSpeech` + `UtteranceProgressListener.onRangeStart`(API 26+)로 읽는 위치 강조.
- 읽을 텍스트: 리플로 문서는 장 단위 정규화 텍스트를 문장 단위로 잘라 `getMaxSpeechInputLength()`(보통 4000자) 이하 묶음으로 큐잉. 각 묶음은 (장, 문자 오프셋) 표를 가져 화면 쪽 이동·강조와 연결.
- 한국어 음성 확인: `isLanguageAvailable(Locale.KOREAN)` 결과가 MISSING_DATA/NOT_SUPPORTED면 `TextToSpeech.Engine.ACTION_INSTALL_TTS_DATA` 또는 TTS 설정으로 안내.
- 백그라운드: Media3 `MediaSessionService` + 포그라운드 서비스(`foregroundServiceType="mediaPlayback"`), `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`(14+), `POST_NOTIFICATIONS`(13+ 실행 중 요청).
- 볼륨 키: TTS 재생 중이면 `onKeyDown`에서 소비하지 않음(시스템 음량). 잠자기 타이머는 서비스 안 코루틴 타이머, '장 끝까지'는 장 경계 도달 시 정지.

### 7.2 저장소 접근 (F-01, F-06, N-04, N-09)

| Android | 방식 |
|---|---|
| 11+ | `MANAGE_EXTERNAL_STORAGE` 요청(안내 화면 → `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`). 거부 시 SAF `OPEN_DOCUMENT_TREE` + `takePersistableUriPermission` |
| 10 | `READ_EXTERNAL_STORAGE` + `requestLegacyExternalStorage="true"` |
| 8~9 | `READ_EXTERNAL_STORAGE` (`maxSdkVersion` 지정 안 함: 11+에서는 MANAGE가 대신함) |

- 수집: 기본 `Download/**`, 사용자 폴더 추가·제외. `java.io.File` 순회(SAF는 `DocumentsContract` 자식 질의), 앱 시작·복귀 시 증분 스캔(경로+크기+mtime이 같으면 해시 재계산 생략).
- 열기: 네이티브 엔진에는 `ParcelFileDescriptor`를 열어 MuPDF `SeekableInputStream`(FileChannel 위 구현) 또는 fd 번호를 넘긴다. 원본은 읽기 전용으로만 연다(`"r"`), 쓰기 API 호출 없음(N-04).
- 외부 열기(F-05·06): `content://`를 앱 캐시 `oneshot/`에 복사 후 열고 닫을 때 삭제. '서재에 추가'면 `filesDir/library/`로 이동.
- 압축 해제(N-09): 캐시 안 문서별 폴더, 정규화 경로가 대상 폴더 밖이면 거부(zip slip), 누적 500MB 상한, 압축비 100:1 초과 항목 거부, 닫으면 삭제.
- **solid CBR(PM 결정, N-09 예외)**: RAR4 아카이브 헤더 플래그(0x0008)·RAR5 아카이브 플래그(0x0004)를 직접 읽어 판별(libarchive 공개 API에 solid 조회 함수가 있는지는 미확인). solid면 처음 열 때 백그라운드에서 앞에서부터 차례로 끝까지 풀어 `cache/comic/<docId>/`에 쪽 파일로 저장(첫 쪽이 풀리는 즉시 표시). **진행 상태**는 `ExtractProgress(done, total, bytes)` StateFlow로 내보낸다: total은 헤더 목록을 먼저 한 번 훑어 얻고(solid라도 헤더 읽기는 빠름), UI는 S-41/S-40 위치에 '만화 준비 중 42/210쪽' 얇은 막대를 표시. 아직 안 풀린 쪽으로 이동하면 그 쪽은 바탕색 빈 종이 + 진행 표시(N-02 v0.6.2 예외), 풀리면 교체. 쪽 목록 그리드·슬라이더 미리보기는 풀린 쪽만 축소 그림, 나머지는 쪽 번호. 500MB 상한·zip slip·압축비 검사는 그대로 적용하고, 상한을 넘으면 그 지점까지만 캐시하고 이후 쪽은 필요할 때 처음부터 다시 풀어 읽는다(느림 안내). 이 캐시는 문서를 닫아도 지우지 않고(재해제 비용 회피) 문서별 LRU로 전체 1GB 상한, 설정의 캐시 지우기로 삭제. 비-solid RAR·CBZ는 기존대로 F-58 범위만 해제.

### 7.4 문서 식별 해시 (F-63)

```
doc_id = hex(SHA-256( "ASH1" || size(uint64 LE) || 앞 64KiB || 가운데 64KiB || 뒤 64KiB ))[0:32]
```
- 파일이 192KiB 이하이면 전체를 해시.
- 요구사항의 "앞뒤 일부와 크기"에 **가운데 표본을 추가**했다: 같은 서식으로 만든 HWP/DOCX(OLE·ZIP 머리/꼬리 구조가 비슷)는 크기·앞뒤가 같을 수 있어서다. **PM 승인(2026-10-22)**.
- 해시 형식은 접두어 `ASH1`로 버전을 둔다. 바꿀 때는 `ASH2`로 올리고 DB에 옛 해시 열을 남겨 이어 읽기를 유지한다.
- 이동·이름 변경: 같은 `doc_id`가 새 경로에서 발견되면 `file_locations`만 갱신.

### 7.5 백업 형식 (F-70)

- 파일: `ASH백업_YYYY-MM-DD.ashbak`(화면 설계서 S-53 기준, 같은 날 두 번째부터 `_2` 붙임, 실체는 ZIP), SAF `CREATE_DOCUMENT`로 저장, `OPEN_DOCUMENT`로 가져오기.
- 내용: `manifest.json`(`schemaVersion`, `appVersionCode`, `createdAt`, 항목 수), `library.json`(documents·progress·bookmarks·highlights·series·reading_sessions·store_shortcuts·scan_folders, 경로 대신 `doc_id` 기준), `settings.json`(DataStore 전체), 선택: `fonts/`(사용자 글꼴 — 백업 화면 '내 글꼴도 넣기' 스위치(M-11), 기본 끔, 켜면 크기 표시).
- 제외: 문서 원본, 캐시(칸 인식·쪽 수 계산·solid CBR 해제본은 재계산 가능, AI 화질 향상 캐시 제외 F-73), 암호.
- 복원: 기본 '합치기' = `doc_id` 기준 병합, 같은 항목은 `updated_at` 최신 우선. '모두 바꾸기'(S-53, M-11) = 먼저 현재 기록을 앱 내부 `filesDir/backup/before-restore.ashbak`으로 자동 저장(1개만 보관, 되돌리기용) → 한 Room 트랜잭션에서 사용자 데이터 테이블(documents·progress·bookmarks·highlights·series·reading_sessions·store_shortcuts·scan_folders) 삭제 후 넣기, DataStore 설정 교체 → 실패 시 롤백하고 설정도 원래 값으로. 캐시 테이블(panel_cache·layout_cache·extract_state)은 지우지 않음(doc_id 기준이라 그대로 유효). 백업에 있는 문서 중 이 기기에서 아직 발견되지 않은 것은 '파일 없음' 상태로 넣고, 서재 스캔에서 같은 doc_id가 발견되면 이어진다. `schemaVersion`이 앱보다 높으면 거부. 미리보기(문서 수·책갈피·형광펜 수)는 `manifest.json`의 항목 수로 보여 준다.

## 8. N-05 보안

1. **INTERNET 권한 차단(CI)**: `build-logic`의 컨벤션 플러그인에서 AGP Variant API로 병합 매니페스트를 받아 검사.
   ```kotlin
   androidComponents.onVariants { variant ->
     val t = tasks.register<CheckForbiddenPermissions>("check${variant.name.cap()}Permissions") {
       mergedManifest.set(variant.artifacts.get(SingleArtifact.MERGED_MANIFEST))
       forbidden.set(listOf("android.permission.INTERNET"))
       warnOnly.set(listOf("android.permission.ACCESS_NETWORK_STATE"))
     }
     tasks.named("assemble${variant.name.cap()}").configure { dependsOn(t) }
   }
   ```
   태스크는 XML을 파싱해 `<uses-permission android:name=…>`에 금지 항목이 있으면 `GradleException`. 추가로 CI 마지막 단계에서 **최종 서명 APK**에 `aapt2 dump permissions <apk>`를 돌려 `android.permission.INTERNET`이 있으면 실패(M-14).
   - **`tools:node="remove"`는 쓰지 않는다(P7, M-14)**: 매니페스트에서 권한만 지우면 라이브러리 코드가 네트워크를 쓰려다 `SecurityException`으로 죽거나, 권한 없이도 다른 경로로 통신을 시도하는 코드가 남는다. INTERNET을 요구하는 의존성이 생기면 **그 의존성을 빼거나 대체**한다. 병합 매니페스트 검사가 실패하면 CI 로그에 어느 라이브러리 매니페스트에서 왔는지(`manifest-merger-blame-*-report.txt`)를 함께 출력한다.
   - **음성 시험(M-14)**: CI에 '일부러 INTERNET 권한을 넣은 시험용 매니페스트 조각(`src/permissionCanary/AndroidManifest.xml`)으로 빌드하면 검사 태스크가 반드시 실패하는지' 확인하는 작업을 둔다(검사가 조용히 꺼지는 것 방지). 이 변형은 배포 산출물에 쓰지 않는다.
   - 의존성 추가 시 점검: 새 AAR의 매니페스트·`classes`에서 `java.net.Socket`/`HttpURLConnection`/OkHttp 참조를 `gradle dependencies` + 간단한 바이트코드 검사로 목록화(경고만).
2. `android:allowBackup="false"`, `android:fullBackupContent="false"`, `android:dataExtractionRules`(12+, cloud-backup·device-transfer 모두 exclude). 
3. **WebView 미사용**: EPUB·HTML은 MuPDF로만 표시 → JS 실행 경로 없음. MuPDF는 `FZ_ENABLE_JS=0`(PDF 폼 JS·mujs 제외)로 빌드, 안드로이드 빌드에 curl 없음 → 원격 리소스 로드 불가. 정규화 단계에서 `<script>`, `on*` 속성, `http(s)://` 리소스 참조 제거.
   - 앞으로 WebView를 쓰게 되면: `javaScriptEnabled=false`, `blockNetworkLoads=true`, `allowFileAccess=false`, `allowContentAccess=false`, `shouldInterceptRequest`에서 앱 내부 가상 호스트 외 모두 빈 응답.
4. 사용자가 실행한 공유(ACTION_SEND, 서점 앱 실행, 사전 넘기기)는 외부 전송에서 제외(요구사항 ④).
5. 매니페스트 `<queries>`: 예스24 등 기본 서점 패키지, `kr.vici.malgeul`, `ACTION_PROCESS_TEXT` intent, `MAIN/LAUNCHER` intent. `QUERY_ALL_PACKAGES` 금지 목록에도 추가.
